# 采购单批量收货 PRD

## 一、需求背景

采购员收货时，若一次有多张采购单到货，目前需要逐张进入采购单操作，效率较低。需要提供采购单批量收货能力，支持采购员通过页面输入或文件导入的方式，一次完成多张采购单、多个 SKU 的收货。

## 二、需求收益

- 减少逐张采购单操作，提高批量收货效率。
- 统一校验采购数量、累计收货和剩余可收数量，降低错收、超收风险。
- 兼容采购员知道团队和不知道团队两种场景，由系统完成采购明细分配。

## 三、入口及数据范围

采购单列表顶部新增【批量收货】按钮，无需勾选采购单即可进入。

- 外层已勾选采购单时，弹窗自动带入对应采购单号作为默认筛选条件。
- 仅展示状态为【待收货】或【部分收货】的采购单。
- 仅展示剩余可收数量大于 0 的 SKU 明细。
- 剩余可收数量：`min（累计到货 - 累计收货，采购数量 - 累计收货）`，小于 0 时按 0 处理。

## 四、批量收货弹窗

弹窗包含两个 Tab：

1. 【输入收货】：在页面中查询明细并填写本次收货数量。
2. 【导入收货】：下载标准模板、整理收货数据后上传文件完成收货。

### 1. 输入收货

#### 筛选条件

| 筛选项 | 组件及规则 |
|---|---|
| 采购单号 | 文本输入，支持多个值，使用逗号或空格分隔 |
| SKU 类型 | 单选下拉，枚举值为【SKU】【领星 SKU】 |
| SKU 编号 | 根据所选 SKU 类型查询，支持多个值，使用逗号或空格分隔 |
| 采购计划号 | 文本输入，支持多个值，使用逗号或空格分隔 |
| 团队 | 多选下拉 |
| 供应商 | 多选下拉 |
| 采购仓库 | 多选下拉 |

#### 明细字段

1. 采购单号
2. SKU
3. 领星 SKU
4. 品名
5. 供应商
6. 采购仓库
7. 采购计划
8. 团队
9. 采购数量
10. 累计收货
11. 剩余可收
12. 本次收货数量（必填）

提供【按剩余可收数量填充】按钮，仅对当前筛选结果中的可见明细进行填充。

### 2. 导入收货

#### 导入类型

当前仅支持【按单导入】。

#### 模板下载

点击【下载模板】打开以下金山文档：

[【金山文档｜WPS 云文档】采购单批量收货模板](https://www.kdocs.cn/l/caigDqifgmQq)

模板字段：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 中台采购单号 | 是 | 填写中台采购单号 |
| SKU（易仓 SKU） | 是 | 填写该采购单下的易仓 SKU，不得填写领星 SKU |
| 品名 | 否 | 辅助识别商品，不作为收货明细匹配条件 |
| 团队 | 否 | 填写该采购单及 SKU 关联的团队。填写后，系统将本次收货数量分配至该团队对应的采购明细；如该团队存在多条采购明细，则在各明细间进行平均分配。未填写时，系统将在该采购单及 SKU 对应的全部可收货明细间进行平均分配 |
| 本次收货数量 | 是 | 必须为大于 0 的整数 |

支持 `.xlsx`、`.xls`、`.csv` 文件，单次仅可导入一个文件，不允许修改模板表头。

## 五、导入匹配及分配规则

采购单明细颗粒度为：

`采购单号 + 采购计划 + SKU + 团队`

同一个采购单号、同一个 SKU、同一个团队下，可能存在多条不同采购计划的采购明细。

### 1. 填写团队

- 系统按【中台采购单号 + SKU + 团队】匹配全部可收货明细。
- 本次收货数量仅在该团队对应的采购明细间分配。
- 若同一团队存在多条采购明细，则在这些明细间平均分配。

### 2. 未填写团队

- 系统按【中台采购单号 + SKU】匹配全部可收货明细。
- 本次收货数量在匹配到的全部采购计划及团队明细间平均分配。

### 3. 通用分配规则

- 单条采购明细的分配数量不得超过其剩余可收数量。
- 分配数量仅允许为整数。
- 如无法整除，余数优先分配至剩余可收数量较大的明细。
- 某条明细达到剩余可收上限后，未分配数量继续在其他可收货明细间重新平均分配。
- 各明细最终分配数量之和必须等于导入行的本次收货数量。
- 若匹配明细的剩余可收数量合计小于本次收货数量，则该导入行校验失败，不执行部分收货。

页面红字提示文案：

> 2. 系统将按采购单号、SKU 及团队匹配可收货明细：填写团队时，仅在该团队对应的采购明细间分配；未填写团队时，在该采购单及 SKU 对应的全部可收货明细间分配。单条明细的分配数量不得超过其剩余可收数量；如无法整除，余数优先分配至剩余可收数量较大的明细，确保各明细分配数量之和等于本次收货数量。

## 六、校验及异常规则

| 场景 | 系统处理 |
|---|---|
| 采购单不存在或状态不支持收货 | 校验失败，提示对应采购单号 |
| SKU 不属于该采购单 | 校验失败，提示采购单号及 SKU |
| 填写的团队不属于该采购单及 SKU | 校验失败，提示团队不匹配 |
| 未匹配到剩余可收大于 0 的明细 | 校验失败，提示无可收货明细 |
| 本次收货数量为空、非整数或小于等于 0 | 校验失败，提示正确填写数量 |
| 本次收货数量超过匹配明细的剩余可收合计 | 校验失败，提示最大可收数量 |
| 文件格式或表头不正确 | 阻止导入并提示具体原因 |

文件校验通过后方可确认导入；校验不通过时不执行部分数据收货。

## 七、收货结果及状态

收货成功后：

- 明细累计收货数量 = 原累计收货数量 + 本次分配数量。
- 明细在途数量 = `max（0，原在途数量 - 本次分配数量）`。
- 记录收货人、收货时间及收货来源；导入收货需记录导入文件名称。
- 采购单累计收货达到采购数量时，状态流转为【已完成】。
- 采购单存在收货但未全部收完时，状态流转为【部分收货】。
- 收货失败时不更新采购单及采购明细数据。

## 八、验收标准

- [ ] 批量收货弹窗包含【输入收货】和【导入收货】两个 Tab。
- [ ] 输入收货支持在【SKU】【领星 SKU】之间切换查询。
- [ ] 输入收货列表在 SKU 后展示【领星 SKU】字段。
- [ ] 仅展示待收货、部分收货且剩余可收大于 0 的明细。
- [ ] 下载模板打开指定的金山文档模板。
- [ ] 导入文件支持 `.xlsx`、`.xls`、`.csv`，单次仅导入一个文件。
- [ ] 团队填写时，仅在指定团队对应的采购明细间分配。
- [ ] 团队未填写时，在采购单号及 SKU 对应的全部可收货明细间分配。
- [ ] 同一团队存在多条采购计划明细时，可按规则继续分配。
- [ ] 单条明细分配数量不超过其剩余可收数量，分配总数等于本次收货数量。
- [ ] 导入数据不符合规则时，明确提示错误原因且不执行部分收货。
- [ ] 收货成功后，累计收货、在途数量和采购单状态更新正确。

## 九、待确认问题

- 同一次导入中，同一采购单号、SKU 是否允许同时存在“填写团队”和“未填写团队”的数据行。
- 同一采购单号、SKU、团队出现重复数据行时，是阻止导入还是合并数量后处理。
