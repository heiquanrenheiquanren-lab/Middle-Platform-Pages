# 1\.需求背景



备货计划、采购计划、发货计划及采购单页面当前查询能力不足。随着计划及单据数据量增加，用户需要通过编码、计划号、仓库、平台、店铺、团队、时间、创建人及上下游单号等条件快速定位数据。

本次需求在不改变原页面整体 UI 风格、列表结构和既有业务流程的前提下，为四个页面新增统一风格的查询区域，并调整页面业务按钮的位置。

# 2\.需求目标

1. 为四个页面补充满足实际业务检索需要的查询条件。

2. 统一多值输入、多选下拉、日期范围、展开收起及重置行为。

3. 在查询项较多时，通过自适应排列和展开区域控制页面高度。

4. 保留各页面原有列表、状态栏、分页和业务操作逻辑。

5. 降低用户查找计划、采购单及关联上下游单据的操作成本。

# 4\.页面布局与公共交互

## 4\.1 页面结构

页面从上至下依次为：

1. 页面标题。

2. 新增查询区域。

3. 页面原有业务按钮区域，左对齐展示。

4. 原有状态栏及列表工具。

5. 原有数据列表。

6. 原有底部批量操作及分页。

## 4\.2 查询项排列

1. 查询项严格按照各页面查询项配置表中的序号排列。

2. 系统根据页面当前可用宽度依次排列查询项。

3. 默认查询区域最多展示两行查询项。

4. 当前宽度下无法放入前两行的查询项，进入展开区域。

5. 不固定某个查询项必须默认展示或必须隐藏。

6. 浏览器宽度变化时，查询项应按既定顺序重新分配。

7. 查询区域不得产生横向滚动条。

## 4\.3 展开与收起

1. 存在溢出查询项时，在查询区底部正中间展示文字按钮“⌄ 展开”

2. 点击后，在原查询项下方新增行，按既定顺序展示溢出的查询项

3. 一行空间不足时自动换到下一行

4. 展开后按钮文案变为“⌃ 收起”

5. 点击收起后隐藏展开区域，但保留用户已经填写或选择的值

6. 收起后，隐藏条件仍参与查询

7. 当前宽度能够展示全部查询项时，不显示展开/收起按钮

## 4\.4 查询与重置

|场景|规则|
|---|---|
|点击查询|按当前所有查询条件刷新列表|
|条件关系|**不同查询项之间使用 AND 关系**|
|查询分页|每次发起新查询后返回第 1 页|
|重置|清空用户输入和选择，恢复页面默认条件|
|查询成功|刷新列表并更新总条数|
|无数据|展示统一空状态，不显示错误提示|
|查询失败|保留当前查询条件，提示“查询失败，请稍后重试”|

## 4\.5 多值文本输入



1. 支持中文逗号、英文逗号、空格和换行分隔多个值。

2. 查询前自动去除每个值首尾空格

3. **查询前自动过滤空值及完全重复的值。**

4. 输入框占位文字应明确提示支持多个值。

## 4\.6 日期范围

1. 日期查询由“时间类型＋开始日期＋结束日期”组成。

2. 点击日期输入区域后弹出日期选择器。

3. 开始日期和结束日期必须同时填写或同时为空。

4. 开始日期不得晚于结束日期。

5. 查询范围包含开始日期和结束日期当天。

6. 各页面查询项配置

# 7\.页面状态及兼容规则



1. 本次仅增加查询功能，不新增业务状态。

2. 页面原有状态 Tab 查询逻辑保持不变。

3. 状态 Tab 与新增查询条件之间使用 AND 关系。

4. 切换状态 Tab 后保留当前查询条件，并从第 1 页加载结果。

5. 原列表排序规则保持不变。

6. 原页面分页条数选项保持不变。

7. 历史数据应支持通过新增查询条件检索；若历史字段为空，则按空值处理。



# 8\.异常与边界场景

|场景|系统处理|用户提示|
|---|---|---|
|只填写开始日期或结束日期|阻止查询|请选择完整的时间范围|
|开始日期晚于结束日期|阻止查询|开始日期不能晚于结束日期|
|多值输入包含重复值|自动去重后查询|无需提示|
|多值输入包含连续分隔符|忽略空值|无需提示|
|查询无匹配数据|展示空状态|暂无符合条件的数据|
|查询接口失败|保留查询条件和当前列表|查询失败，请稍后重试|
|下拉数据源加载失败|下拉显示失败状态，允许重新加载|选项加载失败，请重试|
|用户输入无权限数据|返回空结果，不泄露数据|暂无符合条件的数据|
|默认创建人账号已停用|创建人默认值为空|无需提示或按用户中心规则处理|
|浏览器宽度变化|重新分配默认区与展开区查询项|无需提示|
