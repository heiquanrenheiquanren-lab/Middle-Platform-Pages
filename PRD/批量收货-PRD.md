# 批量收货 PRD

## 一、需求背景

采购员收货时，若一次有多张采购单到货，目前只能在列表中逐张进入单条收货弹窗操作，效率低、易出错。需要提供「批量收货」能力，让采购员一次性对多张采购单、多个 SKU 统一录入本次收货数量，一次提交完成收货。

## 二、需求收益

- 提升收货效率：一次录入多张采购单、多个 SKU 的收货数量，减少重复进出弹窗。
- 降低漏收/错收：在统一表格中横向对照采购数、累计收货、剩余可收，减少人工核对成本。
- 操作更灵活：支持在弹窗内按采购单号、SKU 等条件检索后再收货，不必先在外层列表勾选。

## 三、需求范围

### 1. 入口

采购单列表顶部【批量收货】按钮。

- 不再强制要求先勾选采购单，任何时候均可点击进入弹窗。
- 若外层已勾选采购单，进入弹窗时自动将这些采购单号带入弹窗内的「采购单号」搜索框，默认只看这些单；清空或修改条件后可检索其它单。

### 2. 数据范围

弹窗内仅展示满足以下条件的明细：

- 采购单状态为【待收货】或【部分收货】；
- SKU 的**剩余可收 > 0**（剩余可收为 0 的 SKU 不展示、不可检索）。

剩余可收口径：

`剩余可收 = min(累计到货 - 累计收货, 采购数量 - 累计收货)`，结果小于 0 时按 0 处理。

## 四、弹窗交互与布局

- 弹窗**固定高度**，不随筛选结果或数据多少变化；数据多时在明细表格区内部滚动。
- 弹窗**不出现横向滚动**，通过合理分配列宽保证一屏展示。
- 左固定列：采购单号、SKU；右固定列：本次收货数量。横向滚动时这些列始终可见。
- 品名列过长时显示省略号，鼠标悬停展示完整品名。
- 「查询」「重置」按钮始终与筛选条件在同一行，不单独占一行。
- 各筛选组件提供一键清空「×」，可单独去掉某个搜索条件。

## 五、筛选条件

弹窗内支持以下筛选，多条件之间为「并且」关系：

| 筛选项 | 组件 | 说明 |
|---|---|---|
| 采购单号 | 文本输入 | 支持输入多个，用逗号/空格分隔，匹配任一 |
| SKU | 文本输入 | 支持输入多个，用逗号/空格分隔 |
| 采购计划号 | 文本输入 | 支持输入多个，用逗号/空格分隔 |
| 团队 | 多选下拉 | 精确匹配 |
| 供应商 | 多选下拉 | 精确匹配 |
| 采购仓库 | 多选下拉 | 精确匹配 |

## 六、明细表格字段

列顺序如下：

1. 采购单号（左固定）
2. SKU（左固定）
3. 品名（超长省略号，悬停看全名）
4. 供应商
5. 采购仓库
6. 采购计划
7. 团队
8. 采购数量
9. 累计收货
10. 剩余可收
11. 本次收货数量（右固定、必填）

## 七、操作与校验

### 1. 一键填充

提供【按剩余可收数量填充】按钮，点击后按当前筛选结果，将可见行的「本次收货数量」自动填充为各行的剩余可收数量。

### 2. 提交校验

点击【确认收货】时校验：

- 可见且剩余可收 > 0 的行，本次收货数量必填；
- 本次收货数量必须为不小于 0 的整数；
- 本次收货数量不得超过该行剩余可收数量。

校验不通过时在对应行提示，并阻止提交。

### 3. 提交逻辑

提交确认后，对填写了收货数量的每一行：

- 该 SKU 累计收货 = 原累计收货 + 本次收货数量；
- 该 SKU 在途数 = max(0, 原在途数 - 本次收货数量)；
- 记录收货人、收货时间、收货备注。

## 八、状态流转

提交后按汇总结果更新采购单状态：

- 累计收货 ≥ 采购数量：**已完成**；
- 0 < 累计收货 < 采购数量：**部分收货**；
- 累计收货 = 0：**待收货**。

## 九、验收标准

- [ ] 【批量收货】按钮无需先勾选即可打开弹窗。
- [ ] 已勾选采购单时，打开弹窗默认带入对应采购单号。
- [ ] 弹窗仅展示【待收货】【部分收货】且剩余可收 > 0 的 SKU。
- [ ] 支持按采购单号、SKU、采购计划号、团队、供应商、采购仓库筛选。
- [ ] 采购单号、SKU 左侧固定，本次收货数量右侧固定，弹窗无横向滚动。
- [ ] 品名过长省略号显示，悬停可看完整品名。
- [ ] 弹窗高度固定，筛选后不变化。
- [ ] 「查询」「重置」与筛选条件同行展示。
- [ ] 本次收货数量必填，且不能超过剩余可收。
- [ ] 「按剩余可收数量填充」可一键填充可见行。
- [ ] 提交后各 SKU 累计收货、在途数、采购单状态正确更新。
