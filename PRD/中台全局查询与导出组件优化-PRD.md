# 中台全局查询与导出组件优化 PRD

## 1. 需求信息

| 项目 | 内容 |
|---|---|
| 需求名称 | 中台全局查询与导出组件优化 |
| 适用范围 | 需求预测、供应商库存、平台仓&海外仓库存、团队库存；全局导出组件适用于所有页面 |
| 版本 | v0.2（评审稿） |
| 需求类型 | 全局组件优化、查询规则优化 |

## 2. 背景与需求效益

### 2.1 背景

当前部分编码类查询为模糊匹配，容易返回相似编码；部分页面下载仅覆盖当前分页，用户需要重复下载或手工合并。现需保留原页面查询区和下载入口，统一编码查询口径，并建设全局导出中心。

### 2.2 需求效益

| 效益 | 说明 |
|---|---|
| 提升查询准确性 | 编码按完整值精确匹配，减少相似 SKU、单据号、批次号等误命中。 |
| 提升导出效率 | 一次导出当前筛选条件下的全部结果，不受分页限制，减少重复操作和人工合并。 |
| 降低使用成本 | 页面原有查询和下载入口保持不变，用户无需重新学习操作路径。 |
| 提升任务可追溯性 | 统一记录导出状态、操作人、时间和失败原因，便于跟进与审计。 |

## 3. 需求目标与范围

### 3.1 目标

1. 指定四类页面的编码查询改为精确匹配，保留原查询组件结构和样式。
2. 所有页面原有下载/导出入口保持不变，导出当前筛选条件下的全部结果。
3. 在顶部菜单、登录账号左侧增加全局导出中心，查看当前用户的导出任务并执行状态对应操作。

### 3.2 不在范围

- 不重做或移动现有查询组件、下载/导出入口。
- 本次不要求所有页面同步改造编码精确查询；全局导出组件按统一规则接入。
- 不定义后端队列、文件存储、权限中心的具体技术实现。

## 4. 功能需求

### 4.1 编码类查询精确匹配

适用页面：需求预测、供应商库存、平台仓&海外仓库存、团队库存。

适用字段包括：SKU、SellerSKU/ASIN、领星 SKU、易仓 SKU、仓库代码、单据号、批次号、跟踪号、供应商代码、供应商料号及其他唯一编码字段。

规则：

1. 输入值必须与数据完整值一致，不支持模糊、包含、前缀或后缀匹配。例如输入 `ABC`，不得命中 `ABC-01` 或 `XABC`。
2. 不改变现有查询组件的结构、位置、样式和基本交互。
3. 保持页面既有批量输入能力；输入值需清理首尾空格、过滤空值、去重，多个编码按 OR 查询。
4. 未命中值不影响其他命中结果；最终匹配以服务端精确查询为准。

### 4.2 全量导出

1. 所有页面原有下载/导出入口保持原位置、名称和形态。
2. 点击后读取当前页面已生效的筛选、状态、排序和模板条件，创建导出任务。
3. 导出当前筛选条件下的全部结果，不受页码、分页大小和当前页可见行数限制。
4. 任务保存筛选条件快照，遵守用户数据权限、字段权限和脱敏规则。
5. 当前结果为空时不创建空文件任务，并提示“当前筛选条件下暂无可导出的数据”。

### 4.3 全局导出中心

入口位于中台顶部菜单右侧、登录账号左侧；从任意页面打开均展示当前登录用户自己的任务。入口显示处理中任务数量角标，名称为“导出中心”。

筛选项：任务类型、模板名称、来源页面、处理状态；不提供时间查询。任务类型为下拉多选，支持在枚举值中模糊搜索；模板名称为文本输入，支持模糊搜索。

模板是用户基于某一任务类型配置的字段组合，用于保存个人常用的导出字段。列表字段：任务类型、模板名称、来源页面、处理状态、操作人、发起时间、完成时间、处理耗时、失败原因、操作。

处理状态仅保留四种：处理中、成功、失败、已取消。

| 状态 | 可操作按钮 | 操作结果 |
|---|---|---|
| 处理中 | 取消 | 点击后任务转为“已取消”，不再生成文件。 |
| 成功 | 下载 | 点击后立即开始下载。 |
| 失败 | 重试、取消 | 重试后任务转为“处理中”；取消后任务转为“已取消”。 |
| 已取消 | 重试 | 点击后任务转为“处理中”。 |

关闭弹窗不影响任务；重新打开后保留任务记录和状态。任务状态变化后列表即时刷新。

## 5. 交互与反馈

- 创建成功：`导出任务已提交，可在右上角导出中心查看`。
- 下载成功：`文件下载已开始`。
- 取消成功：`导出任务已取消`。
- 重试成功：`已重新创建导出任务`。
- 导出失败：展示失败原因，并提供重试、取消。
- 列表加载失败：保留弹窗和筛选条件，提示用户重试。

## 6. 权限、日志与接口要求

1. 导出中心默认仅展示当前用户任务；导出范围沿用来源页面的数据权限。
2. 至少记录任务 ID、任务类型、模板、来源页面、筛选条件快照、操作人、状态、时间、文件标识和失败原因。
3. 记录创建、取消、重试、下载、失败等操作事件。
4. 接口至少支持：创建任务、查询本人任务、查询状态、取消、重试、获取下载文件。
5. 原型阶段使用 mock 数据；真实接口、异步队列策略由研发确认。

## 7. 验收标准

- 四类页面编码查询按完整值精确匹配，不返回编码片段匹配结果。
- 原有查询组件和所有页面原有下载/导出入口位置不变。
- 导出结果覆盖当前筛选条件下的全部数据，不受分页限制。
- 顶部账号左侧存在全局导出中心入口，且仅展示当前用户任务。
- 工作台状态仅有处理中、成功、失败、已取消四种。
- 处理中仅显示“取消”；成功仅显示“下载”；失败显示“重试、取消”；已取消显示“重试”。
- 点击下载立即开始下载；取消、重试后状态正确更新。

## 8. 待研发确认

| 问题 | 影响 |
|---|---|
| 导出服务异步队列、单任务数据量和超时阈值 | 影响处理中、失败和性能策略 |
| 失败重试是原任务转处理中还是创建新任务 | 影响任务审计和任务 ID 规则 |
| 模板名称、任务类型由页面还是服务端维护 | 影响筛选和任务展示 |
