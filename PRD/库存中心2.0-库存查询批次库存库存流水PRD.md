## 二、需求背景、目标与范围

### 2.1 背景

当前中台库存管理主要存在以下问题：

1. **货权归属与销售归属混在同一库存颗粒度中**：当前库存记录同时包含 SKU、仓库、团队、平台、店铺、Seller SKU 等维度，将库存领域的实物位置、货权归属、批次和库龄，与销售领域的平台、店铺、Seller SKU、Listing 强行组合，导致库存记录过细、共享关系不清晰，业务单据也难以使用统一的库存口径；
2. **库存类型及状态口径不规范**：当前存在“在库量”“在库（待发）量”“在途/在产量”等自定义口径，缺少统一的业务定义和状态边界，容易继续衍生“待退量”“待补量”等非标准字段，增加跨团队理解和沟通成本；
3. **库存页面数量过多且视角重复**：现有库存相关页面包含供应商库存、平台仓及海外仓库存、入库批次查询、库存总览、分仓明细、团队库存总览、团队库存分仓明细等多个入口。用户需要频繁切换页面，操作路径长，同一库存数据在不同页面中的展示口径不一致；
4. **缺少统一库存流水**：库存变化缺少可查询、可追溯的记录，无法快速定位某批货每次入库、出库及库存变化的来源，发生库存异常时难以还原原因；
5. **缺少规范化库存底座**：出入库类型、库存占用与释放、批次扣减、业务单据与库存变化之间尚未形成统一规则，不同业务模块容易各自处理库存，造成口径和数据结果不一致。

### 2.2 目标

1. 通过【库存查询】提供统一的当前库存余额视图；
2. 通过【批次库存】追溯适用仓库的入库来源、剩余可用库存和库龄；
3. 通过【库存流水】追溯可用库存的实际增加和减少；
4. 三个页面采用一致的 SKU、仓库和团队口径，并支持条件联动；
5. 对未知值、无数据和不适用字段进行明确区分，不使用 `0` 代替未知值；
6. 查询和导出遵守数据权限，并保留必要的操作记录。

### 2.3 本次包含

1. 【库存查询】页面的筛选、列表、合计、弹窗、导出和零库存规则；
2. 【批次库存】页面的筛选、列表、详情、导出和批次适用范围；
3. 【库存流水】页面的筛选、列表、批次号展示和导出；
4. 三个页面之间的条件传递；
5. Amazon FBA 在三个页面中的特殊展示；
6. 页面所需的数据权限、空值、异常和审计要求；
7. 统一库存变动引擎，包括库存增减、占用与释放、冻结与解冻、批次扣减、FIFO、库存流水、可用库存校验、幂等和并发控制。

### 2.4 本次不包含

1. 各海外仓服务商接口的技术字段文档；
2. 单位库存成本构成和移动加权平均价计算（作为另外一个单独的需求）。

## 三、统一业务口径

本章是三个页面共用的唯一口径来源。各页面章节不重复定义相同规则。

### 3.1 库存颗粒度

#### 3.1.1 通用库存

```text
SKU + 仓库 + 团队
```

1. 同一 `SKU + 仓库 + 团队` 在库存余额中只能存在一份正式库存记录；可用、占用、冻结和在途是该库存记录下的数量状态，不得拆成多份互相独立的库存；
2. 批次是该库存余额下的来源和库龄明细，不作为库存余额主键。

#### 3.1.3 中台只做一套正式库存口径

1. 关于海外仓、平台仓的库存，中台只做一套库存口径；
2. 系统不并列展示或维护“中台逻辑库存”和“海外仓结果库存”两套业务库存，避免业务人员选择不同库存口径；
3. 中台的库存要加上【团队】颗粒度。

### 3.2 库存数量、状态与出入库类型

#### 3.2.1 库存数量与状态

| 字段 | 定义 | 是否计入在库总量 |
|---|---|---:|
| 可用库存 | 当前可继续被业务使用的数量 | 是 |
| 占用库存 | 已被业务单据锁定、仍在仓内的数量 | 是 |
| 冻结库存 | 因质量、盘点、争议或人工控制暂不可用的在库数量 | 是 |
| 在库总量 | 当前仓库内已确认存在的实物数量 | — |
| 在途库存 | 已发出但尚未完成目标仓入库的数量 | 否 |
| 待采购库存 | 非实物库存，不参与在库数量；具体业务含义、来源单据及数量计算口径待确认 | 否 |

统一公式：

```text
在库总量 = 可用库存 + 占用库存 + 冻结库存
可用库存 = 在库总量 - 占用库存 - 冻结库存
库存总量 = 在库总量 + 在途库存
```

页面规则：

1. 数量为确定的零时显示 `0`；
2. 字段不适用或未取得可靠映射时显示 `—`；
3. 不得使用 `0` 代替未知值；
4. 待采购库存不属于实物库存，不参与在库总量、库存总量、批次或库存流水；
5. 备货计划、发货计划等业务判断优先使用可用库存，不得直接使用在库总量替代；
6. “虚拟库存/虚拟入库”不纳入本次正式库存状态；供应商直发等场景后续单独设计；
7. 外部系统的可用、占用、冻结、不可售等状态不得直接照搬，接入时必须建立外部状态到中台状态的映射；无法可靠映射的字段显示 `—`，不得按 0 处理；
8. 中台业务占用与海外仓返回的占用是否完全对应尚未确认，在规则明确前不得重复累计为两份占用；
9. “库存总量”是底层统计口径，本次库存查询列表不新增同名字段，页面继续分别展示在库总量和在途库存。

#### 3.2.2 出入库类型

出入库类型用于回答“库存因为什么业务增加或减少”，是库存流水、来源追溯和后续进销存统计的基础。

**入库类型：**

| 入库类型 | 业务含义 | 典型来源单据 |
|---|---|---|
| 采购入库 | 采购商品完成收货并进入库存 | 采购单、采购收货单 |
| 加工入库 | 子件加工完成后，组合成品进入库存 | 加工单 |
| 调拨入库 | 库存从其他仓库调入并完成目标仓入库 | 调拨单 |
| 盘盈入库 | 盘点后实物数量大于系统数量，按差异增加库存 | 盘点单、损益单 |
| 退货入库 | 非销售退件类的退回商品重新进入库存 | 退货单 |
| 赠品入库 | 无采购价赠品或业务赠品进入库存 | 赠品入库单或对应业务单据 |
| 销售退件入库 | 已销售商品退回并确认重新入库 | 销售退货单、退件入库单 |

**出库类型：**

| 出库类型 | 业务含义 | 典型来源单据 |
|---|---|---|
| 销售出库 | 因销售订单履约实际扣减库存 | 销售订单、销售出库单 |
| 调拨出库 | 库存从当前仓库发往其他仓库 | 调拨单 |
| 加工出库 | 子件因库内加工被实际消耗 | 加工单 |
| 盘亏出库 | 盘点后实物数量小于系统数量，按差异扣减库存 | 盘点单、损益单 |
| 报损出库 | 商品损坏、丢失或确认不可用后扣减库存 | 报损单、损益单 |
| 样品出库 | 商品因送样、测试或展示用途离开库存 | 样品申请单、样品出库单 |

统一规则：

1. 每一笔可用库存增加或减少的库存流水必须标记一个明确的出入库类型；
2. 出入库类型回答库存如何变化，来源单据回答由哪张业务单据触发，两者不得混为一个字段；
3. 没有出入库类型的库存变化不得进入正式库存账，也无法纳入进销存统计；
4. 不允许通过页面或数据库直接修改库存余额，所有库存增减必须由具有明确出入库类型的业务动作产生；
5. 占用、释放、冻结、解冻属于库存状态管理，不属于入库或出库类型；按本 PRD 已确认口径，不在【库存流水】页面单独生成流水；
6. 新增出入库类型必须经过统一枚举评审，不允许各业务模块自行创建含义重复的类型；
7. 进销存报表后续按照出入库类型归集期初、本期入库、本期出库和期末数量；金额口径另由财务成本专项方案定义。

#### 3.2.3 库存占用与释放

库存占用表示业务单据预先锁定可用库存，防止同一库存被其他业务重复使用。占用不等于实际出库，必须由具体业务单据产生，并通过独立的占用明细进行管理。

**会产生库存占用的典型业务单据：**

- 发货单；
- 销售订单；
- 库内加工单；
- 调拨单；
- 备货任务；
- 后续经评审确认需要预留库存的其他执行单据。

每一笔占用明细至少记录：

| 字段 | 说明 |
|---|---|
| 占用方 | 发起占用的业务模块或业务主体 |
| 来源单据 | 单据类型、单据号及单据明细ID |
| 库存范围 | SKU、仓库、团队 |
| 原始占用数量 | 首次成功锁定的数量 |
| 已执行数量 | 已通过实际出库、加工消耗等动作执行的数量 |
| 已释放数量 | 因取消、作废、差异或单据完结释放的数量 |
| 剩余占用数量 | 当前仍被锁定的数量 |
| 占用状态 | 占用中、部分执行、已完成、已取消、已释放 |
| 时间及操作记录 | 创建、执行、释放、完结时间及操作人/任务 |

数量关系：

```text
剩余占用数量 = 原始占用数量 - 已执行数量 - 已释放数量
```

处理规则：

1. 创建占用前，库存变动引擎必须按 `SKU + 仓库 + 团队` 重新校验最新可用库存；可用不足时整笔占用失败；
2. 占用成功后，可用库存减少、占用库存增加，在库总量不变；
3. 实际执行时，以实际执行数量扣减占用库存和实物在库数量，不得继续使用计划数量直接扣库；
4. 单据完成、取消或作废时，剩余占用必须全部释放，占用库存减少、可用库存恢复；
5. 单据进入终态后，该单据的剩余占用数量必须等于 0；
6. 同一单据重复提交占用、执行或释放请求时，必须使用幂等键防止重复处理；
7. 占用、执行和释放必须保留明细记录，不允许只在库存余额中维护一个无法追溯来源的占用数字；
8. 按本 PRD 已确认的页面口径，占用、释放本身不在【库存流水】页面单独生成流水，其过程由占用明细追溯；实际出库按 3.5 库存流水规则记录。

示例：

```text
发货单计划发货100：可用库存-100，占用库存+100
实际发货99：已执行数量+99，占用库存-99，实物在库数量-99
单据完成：剩余占用1自动释放，可用库存+1，占用库存-1
最终结果：已执行99，已释放1，剩余占用0
```

### 3.3 批次规则

1. 本次仅自营仓、物流中转仓生成并展示批次；
2. 平台仓、海外仓、供应商仓不进入【批次库存】页面；
3. 批次明细颗粒度为：

```text
批次号 + SKU + 仓库 + 团队
```

4. 同一入库批次可包含多个 SKU；同一 SKU 分属不同团队时必须拆分批次明细；
5. 批次号生成规则：`PC + 入库日期YYMMDD + 当日4位流水号`，每天从 `0001` 开始顺延；
6. 任何出库类型均按照入库批次先进先出。

拆分逻辑说明：同一张入库单在同一时间完成一次收货时，可以同时包含多个 SKU。系统先按 SKU 拆分；同一 SKU 如归属多个团队，再按团队拆分。每个唯一的“SKU + 仓库 + 团队”组合分别生成一条独立库存批次明细。

例如，入库单 `RK20261012-001` 于 `2026-10-12 10:00` 一次性完成入库，入库内容如下：

| SKU 编码 | 团队 | 入库数量 |
|---|---|---:|
| SKU-A | A团队 | 60 |
| SKU-A | B团队 | 40 |
| SKU-B | A团队 | 30 |
| SKU-B | C团队 | 20 |
| SKU-C | B团队 | 80 |

该入库事件包含 3 个 SKU、5 个不同的“SKU + 团队”组合，因此应生成 5 条独立库存批次明细：

| 库存批次号 | SKU 编码 | 团队 | 批次入库数量 |
|---|---|---|---:|
| PC2610120001 | SKU-A | A团队 | 60 |
| PC2610120002 | SKU-A | B团队 | 40 |
| PC2610120003 | SKU-B | A团队 | 30 |
| PC2610120004 | SKU-B | C团队 | 20 |
| PC2610120005 | SKU-C | B团队 | 80 |

### 3.4 库龄规则

1. 仅自营仓和物流中转仓计算并展示库龄；
2. 其他仓库不维护本期批次库龄，页面显示 `—`；
3. 批次在库库龄按当前日期与库龄起算日期计算，列表值不附带“天”；
4. 库存查询页的加权库龄按当前剩余可用批次计算：

```text
加权库龄 = Σ（批次剩余可用库存 × 批次库龄）÷ 剩余可用库存合计
```

### 3.5 库存流水规则

1. 库存流水只记录可用库存实际增加或减少；
2. 占用、释放、冻结、解冻及在途状态本身不单独生成本页面库存流水；
3. 每条流水必须记录操作前、操作数量、操作后；
4. 每条流水必须能关联来源单据和操作单号；
5. 涉及批次扣减时记录实际影响的批次号；多个批次号以逗号分隔，超出单元格宽度时省略，悬浮展示完整内容；
6. 已产生的库存流水不得直接修改或删除；更正应通过新的反向或调整业务处理；
7. 业务单据、外部流水重复触发时不得重复生成库存流水。

### 3.6 【重点】外部仓及 FBA 更新规则

#### 3.6.1 通用海外仓

1. **外部仓本身没有团队概念**；
2. **系统通过来源业务单号匹配中台订单、发货单、退货单等，识别 SKU、仓库和团队**；
3. **一条外部库存变动只能归属一个团队**；涉及多个团队时拆分为多条中台记录；
4. **无法识别 SKU、仓库或团队的记录不得静默更新正式库存**；
5. **外部唯一键用于防止重复处理**。

#### 3.6.2 首次初始化差异的团队分配规则

海外仓首次拉取库存明细时，外部系统通常只返回“仓库 + SKU”总量，不包含中台团队。首次重新初始化库存时，按以下第一版简化规则将海外仓实际库存分配到团队：

1. **适用范围**：仅用于海外仓首次接入或重新初始化时的团队库存分配，不用于日常库存流水归属和运行期库存校准；
2. **分配基数**：以中台初始化前同一“仓库 + SKU”下各有效团队的现有库存为比例基数；
3. **比例分配**：按照各团队现有库存占比，对海外仓返回的“仓库 + SKU”实际总量进行分配；
4. **排除名单**：已停止销售、无需继续分配库存的平台或团队，由供应链提供排除名单；被排除团队不参与比例和尾差计算；
5. **特殊团队**：清货团队、低动销团队等第一版仍按通用比例参与分配，初始化完成后可通过中台现有团队调拨或调整能力重新处理；
6. **整数及尾差**：按比例计算后产生小数时，先按统一取整规则计算，再将剩余尾差优先分配给占比较大的团队；同一占比时按固定团队排序处理，确保重复执行结果一致；
7. **数量守恒**：所有团队最终分配数量之和必须等于海外仓返回的该“仓库 + SKU”实际库存总量；
8. **无比例基数**：排除名单生效后，若可参与团队的原库存合计为 0，则不得自动平均或随机分配，应记录初始化异常，待供应链提供归属规则后再执行；
9. **执行留痕**：必须保存初始化前中台数量、海外仓实际数量、参与及排除团队、分配比例、取整结果、尾差归属、初始化批次和执行时间；
10. **后续调整**：初始化完成后，业务认为团队分配不合理的，通过团队调拨或正式调整记录处理，不直接覆盖初始化结果。

示例：

```text
海外仓实际库存：100
团队A初始化前库存：60，占比60%
团队B初始化前库存：30，占比30%
团队C初始化前库存：10，占比10%

初始化分配结果：A=60，B=30，C=10
```

该规则为第一版简化方案。供应链后续如提出更合适且可执行的分配规则，应重新评审并更新本节后实施。

#### 3.6.3 Amazon FBA

1. **Amazon FBA 库存固定归属唯一的亚马逊团队**，中台按 FBA 库存接口返回结果**直接覆盖更新**，**不对接 Amazon FBA 外部库存流水，也不因覆盖更新生成【库存流水】页面数据**；
2. **FBA 行保留【库存流水】入口，打开后展示空状态**；
3. **接口返回的 FBA 仓库必须已在中台维护并完成仓库映射**。接口存在但中台未维护的 FBA 仓库，**不展示该仓库及其库存**；
4. **FBA 不生成本期批次**，加权库龄显示 `—`；
5. **冻结库存尚未取得可靠映射时显示 `—`**。

FBA 库存状态与接口字段映射如下：

| 库存状态 | FBA 对应口径 | 接口参数名 | 规则与备注 |
|---|---|---|---|
| **可用库存** | **FBA 可售** | `data>>afn_fulfillable_quantity` | **不使用“可用总数”**，因为“可用总数”包含实际在途数量 |
| **占用库存** | **FBA 预留** | `data>>afn_reserved_quantity` | FBA 预留由**客户订单预留、运营中心转运和仓内处理中**等类型共同构成，**不可全部等同于客户订单占用** |
| **在途库存** | **实际在途** | `data>>stock_up_num` | **实际在途 = 发货单发货数量 - 签收数量** |
| **在库总量** | **中台计算** | 无 | **在库总量 = 可用库存 + 占用库存 + 冻结库存** |

FBA 预留库存包含以下业务场景：

1. **客户订单预留**：客户下单但尚未发货时，订单数量从可用库存转入预留；订单发货后才从库存中扣除，订单取消后可能恢复为可用库存。该类型最接近中台的订单占用；
2. **运营中心转运**：Amazon 管理库存报告中的 `Reserved Transfer`，对应店铺后台的“运营中心转运”。货物由 Amazon 暂时调配或转运，仍可能允许买家购买，只是履约时间可能不同，因此不能直接视为不可销售库存；
3. **仓内处理中**：库存正在核验尺寸重量、接受调查或等待移除订单处理时进入相关预留，需等待 Amazon 处理完成后才能确定是否恢复可用。

接口文档：[领星查询 FBA 库存列表 V2](https://apidoc.lingxing.com/#/docs/Warehouse/FBAStock_v2?id=%e6%9f%a5%e8%af%a2fba%e5%ba%93%e5%ad%98%e5%88%97%e8%a1%a8-v2)。

参考来源：[Amazon Reserved inventory report 说明](https://sellercentral.amazon.com/help/hub/reference/external/G201723860?locale=en-EN)。

### 3.7 【重点】后续流水的团队归属规则

接口上线后的海外仓库存变动，**优先使用外部流水上的外部单据号匹配中台业务单据，并继承中台单据对应的团队**：

| 外部流水场景 | 团队归属规则 |
|---|---|
| 销售订单出库 | 通过订单号匹配中台销售订单，归属订单所属团队 |
| 发货单入库/上架 | 通过中台发货单及其团队明细确定团队；同一 SKU 涉及多个团队时按 3.8 处理 |
| 销售退货入库 | 优先追溯原销售订单，继承原订单所属团队 |
| 其他可关联中台单据的流水 | 继承对应中台单据的团队 |

统一处理要求：

1. **一条已拆分的中台流水只能归属一个团队**；同一外部流水对应多个团队时，按团队拆分后再更新中台库存；
2. **必须保存外部单据号、中台匹配单据、匹配团队、匹配方式和处理结果**；
3. 调拨、盘盈盘亏及海外仓内部调整等无法取得团队、也无法匹配中台业务单据的流水，**不得随机分摊或直接修改某个团队库存**；
4. **无法归属团队的流水生成待处理记录**，保留原始流水和失败原因，待后续归属规则确认后再处理；
5. 同一外部流水重复拉取时，**依据外部唯一键幂等处理，不得重复更新团队库存**。

### 3.8 【重点】发货单分批上架的团队分配规则

同一张中台发货单中，**同一个 SKU 可能属于多个团队**；海外仓分批上架流水通常**只返回本次上架总量，不返回团队**。本场景按采购分批到货的相同原则处理：

1. **匹配范围**：先通过外部单据号匹配唯一中台发货单，再按发货单中的 SKU 定位所有团队明细；
2. **默认分配**：按照该发货单同一 SKU 下各团队**实际发货数量的比例**，分配本次海外仓上架数量；
3. **数量上限**：每个团队本次分配数量不得超过该团队当前剩余待收数量；剩余待收数量按“团队实际发货数量 - 团队累计收货数量”计算；
4. **分批更新**：每次上架完成后，同步更新各团队累计收货数量和剩余待收数量；
5. **数量守恒**：本次各团队分配数量之和必须等于本次海外仓上架数量；
6. **整数及尾差**：比例分配产生小数时，按照统一取整规则处理；尾差优先分配给当前比例较大且仍有剩余待收数量的团队；
7. **最后一批兜底**：最后一批上架时，以各团队剩余待收数量为准完成分配，消除前序批次取整产生的累计尾差；
8. **超实际发货数量异常**：本次上架数量大于该 SKU 所有团队剩余待收数量合计时，超出部分不得自动分配，生成待处理记录；
9. **幂等处理**：同一海外仓上架流水重复拉取时，不得重复累计收货或重复增加库存。

示例：

某张发货单包含 SKU-A，两个团队的实际发货数量如下：

| 团队 | 实际发货数量 | 分配占比 | 初始剩余待收数量 |
|---|---:|---:|---:|
| A团队 | 60 | 60% | 60 |
| B团队 | 40 | 40% | 40 |
| **合计** | **100** | **100%** | **100** |

海外仓第一次返回 SKU-A 上架数量 50，系统按实际发货数量占比分配：

```text
A团队本次分配 = 50 × 60% = 30
B团队本次分配 = 50 × 40% = 20
本次分配合计 = 30 + 20 = 50
```

第一次上架处理完成后：

| 团队 | 本次分配数量 | 累计收货数量 | 剩余待收数量 |
|---|---:|---:|---:|
| A团队 | 30 | 30 | 60 - 30 = 30 |
| B团队 | 20 | 20 | 40 - 20 = 20 |
| **合计** | **50** | **50** | **50** |

海外仓第二次返回剩余上架数量 50。由于这是最后一批，系统按各团队剩余待收数量完成分配：A团队分配 30，B团队分配 20。处理完成后，A团队累计收货 60、B团队累计收货 40，两个团队的剩余待收数量均为 0，累计收货总量与发货单实际发货总量 100 一致。

### 3.9 统一库存变动引擎（以技术方案为准）

库存变动引擎是所有库存变化的唯一处理入口。采购、发货、销售、调拨、加工、退货、盘点、损益及外部同步等业务模块不得绕过库存引擎直接修改库存余额。

#### 3.9.1 引擎职责

库存变动引擎统一负责：

1. 定时接收并处理外部库存同步任务；
2. 增加库存、扣减库存；
3. 占用库存、释放库存；
4. 冻结库存、解冻库存；
5. 库存调整及正式冲销；
6. 按适用仓库进行批次入库和批次扣减；
7. 按 FIFO 选择和扣减批次；
8. 校验 SKU、仓库、团队、数量状态和可用库存；
9. 根据可用库存的实际增减生成库存流水；
10. 维护占用明细及其执行、释放状态；
11. 使用幂等键防止同一业务请求重复增减库存；
12. 通过并发加锁防止超卖、重复扣减和负库存；
13. 为成本计算保留批次及出入库数据；具体成本算法不在本 PRD 定义。

#### 3.9.2 统一请求信息

业务模块调用库存变动引擎时，至少传入：

| 信息 | 说明 |
|---|---|
| 业务动作 | 入库、出库、占用、释放、冻结、解冻、调整或冲销 |
| 出入库类型 | 适用于实际库存增加或减少，使用 3.2.2 统一枚举 |
| 来源单据 | 单据类型、单据号、明细ID |
| 库存颗粒度 | SKU、仓库、团队 |
| 操作数量 | 本次需要处理的数量 |
| 批次策略 | 指定批次或按 FIFO 自动选择；仅批次适用仓库使用 |
| 幂等键 | 唯一标识本次业务请求，防止重复执行 |
| 操作信息 | 操作人或系统任务、业务时间、请求时间 |

缺少 SKU、仓库、团队、来源单据、操作数量或幂等键时，不得执行正式库存变更。

### 5.5 排序规则

1. 【可用库存】【占用库存】【在途库存】【在库总量】【待采购库存】【冻结库存】【加权库龄】表头展示排序图标；

3. 同一时间仅允许一个字段生效，切换字段时清除原字段排序状态；

5. `—`、空值或未取得可靠数据的值，无论升序或降序均排在有效数值之后；
6. 取消排序后恢复系统默认顺序；导出数据沿用当前排序结果。

5. 历史批次和历史流水不得因当前库存为零而删除。

| 场景 | 系统处理 | 页面表现 |

## 十一、验收标准

### 11.1 统一口径

1. 所有确定数量满足 `在库总量=可用库存+占用库存+冻结库存`；
2. 未知值和不适用值显示 `—`，确定的零显示 `0`；
3. 三个页面按 SKU、仓库和团队使用一致的数据权限；
4. 流水页面只出现可用库存实际增加或减少的记录；
5. 批次页面不出现单位库存成本；
6. 后续海外仓流水能通过外部单据号匹配中台单据并确定团队；无法归属的流水进入待处理，不直接修改团队库存；
7. 发货单分批上架时，各团队本次分配合计等于本次上架数量，累计收货和剩余待收同步更新，重复流水不重复入账；
8. 同一 `SKU + 仓库 + 团队` 只有一份正式库存余额，所有影响库存归属的业务单据均带团队；
9. 单据完成、取消或作废后，剩余占用数量归零，已执行数量与已释放数量可追溯；
10. 重复提交占用、执行、释放或库存增减请求时，不重复修改库存；
11. 库存余额、批次库存、占用明细或库存流水任一适用账本更新失败时，整笔库存操作回滚；
12. 多个请求并发扣减同一库存时，以加锁后的最新可用库存校验，不产生超卖或负库存；
13. 业务页面、备货及发货业务只使用一套正式库存余额，不同时提供“中台逻辑库存”和“海外仓结果库存”两套可选口径；外部快照、差异及校验数据仅用于内部核对和审计。

### 11.2 库存查询

1. 四种编码及产品名称均可独立查询；
2. 前四列固定，横向滚动时保持可见；
3. 在库总量提示公式正确，列表值和合计值使用同一公式；
4. 合计统计全部筛选结果，不只统计当前页；
5. FBA冻结库存未知时显示 `—`；
6. FBA点击库存流水后展示空列表；
7. 列表右上角【隐藏 0 库存数据】默认勾选；勾选时只隐藏六个指定库存字段同时为确定值 `0` 的记录，取消后可展示零库存记录；问号提示文案正确；
8. 所有弹窗居中展示且不显示“只读查询”；
9. 仓库查询下拉项按“仓库名称（仓库编码）”展示，选择后可按原仓库条件正确查询。

### 11.3 批次库存

1. 仅展示自营仓、物流中转仓批次；
2. 批次号符合 `PC+YYMMDD+4位流水号`；
3. 批次号、仓库名称、团队、SKU固定，不参与横向滚动；
4. 筛选项可正常查询并重置，按钮始终可见；
5. 列表和详情均不展示单位库存成本；
6. 在库库龄只展示数值；
7. 批次剩余可用库存合计基于全部筛选结果；
8. 仓库查询下拉项按“仓库名称（仓库编码）”展示，选择后可按原仓库条件正确查询；
9. 列表工具栏左侧展示【导出】，右上角展示【说明】及问号图标，悬浮问号展示批次库存数据范围提示。

### 11.4 库存流水

1. 前三列固定，不参与横向滚动；
2. 操作数量位于操作前和操作后之间；
3. 来源单据后展示操作单号；
4. 操作时间后展示批次号；
5. 多批次号省略、悬浮和导出规则正确；
6. 查询按钮、重置按钮在常用桌面分辨率下完整可见；
7. 库存查询内的流水弹窗不显示SKU查询项，并默认带入仓库；
8. 独立页面与弹窗的核心字段口径一致；
9. 独立页面及库存查询内流水弹窗的仓库下拉项均按“仓库名称（仓库编码）”展示，选择后可按原仓库条件正确查询。
10. 独立页面首次进入及点击重置后，操作日期范围默认选中当天；右上角说明问号展示当天默认范围、支持仓库范围及海外仓流水团队归属规则。

### 11.5 权限与导出

1. 用户不能查询或导出未授权仓库、团队数据；
2. 导出范围与当前筛选条件一致；
3. 导出行为可审计追溯。
