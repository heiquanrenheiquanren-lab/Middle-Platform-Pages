# 供应商列表页面 PRD

## 一、文档信息

| 项目 | 内容 |
|---|---|
| 需求名称 | 供应商列表页面 |
| 需求模式 | 轻量需求 |
| PRD 版本 | 草稿版 |
| 适用模块 | 工作台 → 仓库管理 → 供应商列表 |

## 二、需求背景

当前系统没有统一的供应商列表页面。供应商基础数据主要由业务方提供，并通过数据导入写入数据库。业务人员在生成采购单或其他供应商相关单据时，有时需要判断供应商当前是否处于合作状态，但缺少可直接查询和维护供应商状态的页面入口。

因此新增供应商列表页面，作为供应商基础信息及合作状态的统一查看、维护入口，为后续单据生成和业务校验提供数据基础。

## 三、需求目标与效益

### 3.1 需求目标

1. 建立统一的供应商列表页面，展示供应商名称、供应商代码和合作状态。
2. 支持按供应商名称、供应商代码和合作状态查询供应商。
3. 支持新增供应商、调整合作状态，并保留操作日志。
4. 为采购单及其他供应商相关单据提供可查询的供应商合作状态数据。

### 3.2 需求效益

- **业务效率**：业务人员无需通过数据库或其他人员确认，即可在中台查询供应商信息和合作状态。
- **数据统一**：供应商信息和合作状态集中展示，减少不同业务页面或人工记录之间的信息不一致。
- **风险控制**：在生成采购单及其他供应商相关单据时，可基于统一的合作状态进行判断，降低误选禁用供应商的风险。
- **可追溯性**：新增和状态调整写入操作日志，便于追溯供应商状态变化。
- **后续扩展基础**：为采购单、发货单及其他供应商相关功能复用供应商基础数据提供统一入口。

## 四、功能范围

### 4.1 页面入口

入口位于：工作台 → 仓库管理 → 供应商列表。

本页面暂不设置合作状态 Tab，仅通过查询条件筛选状态。

### 4.2 查询功能

查询项顺序如下：

| 查询项 | 控件 | 规则 |
|---|---|---|
| 供应商名称 | 多选下拉 | 供应商名称枚举支持模糊搜索，多选条件按 OR 匹配 |
| 供应商代码 | 文本输入 | 支持输入多个代码，按完整代码精确匹配，不支持模糊匹配 |
| 合作状态 | 下拉单选 | 枚举值：合作中、禁用；默认不选择，展示全部数据 |

供应商代码支持使用逗号、中文逗号、空格、换行或分号分隔多个代码。

### 4.3 列表功能

列表字段：

1. 供应商名称
2. 供应商代码
3. 合作状态
4. 操作

合作状态使用标签展示：合作中为绿色，禁用为红色。

### 4.4 新增供应商

列表左上方提供「新增供应商」按钮。

新增弹窗字段：

| 字段 | 规则 |
|---|---|
| 供应商名称 | 必填，由用户输入 |
| 供应商代码 | 系统自动生成，不允许手工修改 |
| 合作状态 | 默认合作中 |

保存成功后，供应商数据回显到列表，并写入新增操作日志。供应商名称不可重复；重复时提示用户修改。

### 4.5 编辑供应商

列表操作列提供「编辑」按钮。

- 支持调整供应商合作状态：合作中 / 禁用。
- 供应商名称和供应商代码作为只读信息展示。
- 保存后刷新列表，并记录状态调整或编辑日志。

### 4.6 操作日志

列表操作列提供「日志」按钮，复用发货单的操作日志弹窗，保持全局交互统一。

日志至少展示以下字段：

| 字段 | 说明 |
|---|---|
| 操作类型 | 新增、编辑、状态调整等 |
| 日志内容 | 记录具体变更内容 |
| 操作人 | 执行操作的用户 |
| 操作时间 | 操作发生时间 |

## 五、数据与权限规则

- 供应商基础数据来源于业务方提供的数据，并写入系统数据库；本页面本次不新增供应商批量导入功能。
- 供应商代码作为供应商唯一识别信息，列表查询按完整代码精确匹配。
- 页面展示和操作权限沿用中台现有账号权限体系。
- 供应商状态变更必须保留操作人和操作时间，便于审计和问题追溯。
- 本次只建设供应商数据和状态维护入口；生成采购单或其他供应商相关单据时是否禁止选择“禁用”供应商，需结合具体单据规则另行确认。

## 六、验收标准

1. 用户可以从工作台「仓库管理 → 供应商列表」进入页面。
2. 页面正确展示供应商名称、供应商代码、合作状态和操作列。
3. 供应商名称支持多选及枚举模糊搜索；供应商代码支持多值精确查询；合作状态支持单选筛选且默认不筛选。
4. 用户可以新增供应商，供应商代码自动生成，默认合作中，保存后列表可见。
5. 用户可以编辑供应商合作状态，保存后列表状态更新。
6. 新增和编辑操作均可在日志弹窗中查看，日志字段与发货单日志弹窗保持一致。
7. 重复供应商名称、供应商名称为空等异常场景有明确提示，且不会生成无效数据。

## 七、待确认问题

| 问题 | 影响 |
|---|---|
| 供应商代码的正式生成规则是否为现有最大序号递增，还是由后端统一编码服务生成？ | 影响新增供应商的编码逻辑 |
| 生成采购单或其他供应商相关单据时，选择禁用供应商是否需要强制拦截，还是仅提示？ | 影响下游单据的校验和状态流转 |
| 不同角色是否有供应商数据范围限制，例如按团队、组织或部门隔离？ | 影响页面查询、编辑和日志查看权限 |
