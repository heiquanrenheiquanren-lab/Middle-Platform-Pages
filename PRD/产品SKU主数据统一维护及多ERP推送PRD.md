# 产品列表 PRD

## 一、原型：

> 本文中的“易仓”对应需求描述中的“易昌”，以下统一使用“易仓”。

## 二、需求概述

### 2.1 现状

1. **SKU 维护交互繁琐**：产品资料、采购资料、报关资料和运营资料被拆分维护。用户需在多个页面或标签间切换，才能完成一个 SKU 的信息录入，操作路径长且容易遗漏字段。
2. **重复维护造成数据不一致**：新品创建、老品资料更新时，用户需要分别在中台、领星和易仓维护同一份 SKU 资料，重复录入成本高，且三端资料可能不一致。
3. **一个 SKU 不能维护多个供应商**：现有 SKU 资料无法表达一个产品由多个供应商供货的实际业务关系，无法同时维护各供应商的料号、采购周期、最小起订量和默认供货关系。

### 2.2 目标

1. 建立中台 SKU 主数据维护入口：用户在同一 SKU 信息弹窗中完成产品、尺寸重量、报关与物流、采购、关联辅料及图片资料维护。
2. 以中台为 SKU 主数据维护入口，支持从产品列表将选中的 SKU 手动推送至易仓、领星或同时推送至两个系统，并可查看每个目标系统的执行进度与结果。
3. 支持一个 SKU 绑定多个供应商，并明确一个默认供应商，供后续采购等下游业务使用。
4. 保留新增、编辑、推送及供应商关系变更的操作记录，方便问题追溯。

### 2.3 范围

**本次包含**：

- 产品列表查询、查看、新增、编辑、批量修改、导入修改及操作日志。
- 单一 SKU 信息弹窗内的资料维护与校验。
- 一个 SKU 关联多个供应商及默认供应商维护。
- 选中 SKU 后推送至易仓、领星或同时推送，并展示任务进度、结果和失败重试。

**本次不包含**：

- 由中台保存 SKU 后自动触发对易仓、领星的实时推送；本次采用用户在产品列表主动发起推送的方式。
- 在中台替代易仓、领星的全部产品管理能力。
- 对外部 ERP 已存在但中台尚未维护的 SKU 进行自动拉取、自动合并或冲突裁决。

## 三、业务价值

| 价值对象 | 具体价值 |
|---|---|
| SKU 维护人员 | 在一个入口完成资料维护，减少跨系统与跨页面切换。 |
| 采购团队 | 同一 SKU 可查看和维护多个供货来源，降低供应商切换时的信息缺失。 |
| 运营与仓储团队 | 可按需将确认后的 SKU 资料推送至易仓、领星，并直接查看推送结果。 |
| 数据治理 | 中台形成可追溯的 SKU 主数据、供应商关系和推送任务记录，减少三端数据不一致。 |

## 四、业务流程

### 4.1 目标流程

| 步骤 | 操作角色 | 操作 / 系统处理 | 输出结果 |
|---|---|---|---|
| 1 | 产品维护人员 | 在中台产品列表新增 SKU，或打开已有 SKU 编辑 | 进入 SKU 信息弹窗 |
| 2 | 产品维护人员 | 在一个弹窗内维护基础信息、尺寸重量、报关与物流、采购信息、关联辅料和图片信息 | SKU 资料在中台保存 |
| 3 | 产品维护人员 | 在采购信息中新增多个供应商关系，并指定一个默认供应商 | 建立 SKU 与供应商的一对多关系 |
| 4 | 产品维护人员 | 在产品列表勾选一个或多个 SKU，选择“推送产品 → 推送给易仓 / 推送给领星 / 同时推送给易仓和领星” | 创建推送任务 |
| 5 | 中台系统 | 调用目标 ERP 接口，按 SKU × 目标系统记录执行状态 | 展示待推送、推送中、成功或失败结果 |
| 6 | 产品维护人员 | 查看推送进度；存在失败任务时重试失败项 | 失败任务重新执行，结果留痕 |

### 4.2 推送任务状态

推送状态用于描述**单个 SKU 在单个目标系统**中的执行情况，不改变中台 SKU 的可编辑状态。

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| 待推送 | 任务已创建，尚未开始调用接口 | 取消任务 / 开始推送 |
| 推送中 | 正在请求或等待目标 ERP 返回结果 | 关闭弹窗后任务继续执行；不可重复发起同一任务 |
| 成功 | 目标 ERP 已成功接收并处理本次 SKU 资料 | 查看结果 |
| 失败 | 接口调用失败或目标 ERP 校验未通过 | 查看失败原因、重试失败项 |

## 五、权限清单

本节仅列出需要配置权限的业务操作；**查询、重置和日志**不纳入权限清单。具体权限分配角色由业务方另行配置。

| 权限项 | 对应按钮 / 操作 | 说明 |
|---|---|---|
| 新增产品 | +新增产品 | 新建 SKU 产品档案。 |
| 编辑产品 | 编辑 | 编辑单个 SKU 的产品资料。 |
| 批量编辑 | 批量编辑 | 手工或导入批量修改 SKU。 |
| 导出产品 | 导出 | 导出当前查询结果。 |
| 推送至易仓 | 推送产品 → 推送至易仓 | 向易仓发起 SKU 推送任务。 |
| 推送至领星 | 推送产品 → 推送至领星 | 向领星发起 SKU 推送任务。 |
| 同时推送 | 推送产品 → 同时推送至易仓和领星 | 同时向两个 ERP 发起 SKU 推送任务。 |
| 停用产品 | 停用 | 将启用中的 SKU 切换为停用。 |
| 启用产品 | 启用 | 将停用中的 SKU 恢复为启用。 |
| 删除产品 | 删除 | 删除 SKU；操作前需要二次确认。 |

前端根据已配置权限展示或禁用对应入口；后端接口必须同步校验权限。

## 六、功能需求

### 6.1 产品列表

1. 产品列表展示 SKU、产品信息、领星 SKU、产品类目、销售状态、单位、产品负责人、创建信息、更新信息和操作。
2. 当产品类型为“组合品”时，在 SKU 后展示“组合品”标识；单品不展示“单品”标识。
3. 点击 SKU 打开 SKU 信息弹窗，默认只读；点击“编辑”后才允许修改。
4. 查询区在“产品负责人”后提供“启用状态”单选查询，枚举为：启用、停用；默认查询全部状态。
5. 操作列提供“编辑”“停用 / 启用”“删除”“日志”。所有 SKU 默认启用，启用状态显示“停用”操作；点击停用后切换为停用状态，并将操作替换为“启用”；再次点击启用后恢复启用状态。每次状态切换均记录编辑日志，日志内容为“产品状态更新为：启用 / 停用”。
6. 删除按钮使用红色文字，点击后须二次确认；确认删除后移除 SKU，删除后不可恢复。
7. 日志弹窗统一展示操作类型、日志内容、操作人、操作时间。编辑日志必须逐项记录字段名与变更后的值，格式为“字段名更新为：字段值”；多项变更以中文分号分隔，不得使用“更新了信息”等无法追溯具体值的笼统描述。
8. 支持新增、批量编辑、导入、导出和推送产品。按钮区不使用额外卡片底色，遵循现有 UI 规范。

### 6.2 SKU 信息统一维护

SKU 信息在同一弹窗内展示，通过右侧锚点定位以下内容，用户无需离开当前弹窗：

| 区块 | 维护内容 |
|---|---|
| 基本信息 | SKU、关联 SPU、中文品名、英文品名、产品类型、配货类型、型号、识别码、产品系列、品牌、新品/老品、销售状态、一级类别、二级类别、单位、产品负责人 |
| 尺寸重量 | 单品规格、包装规格、净重、毛重、箱规等已有尺寸重量字段 |
| 报关与物流 | HS code、申报价值、申报中文名、申报英文名、物流属性 |
| 采购信息 | 多供应商关系、供应商料号、采购周期、最小起订量、采购员、默认供应商 |
| 关联辅料 | 辅料 SKU、单位成本、辅料比例、备注 |
| 图片信息 | 产品主图、实物图；支持本地选择和 URL 获取 |

基础信息必填字段：SKU、产品类型、配货类型、一级类别、二级类别、品牌、单位、产品负责人、中文品名。英文品名仅允许填写英文字符。报关与物流中的申报价值为数字必填项；HS code 不含小数点。

### 6.3 多供应商绑定

1. 一个 SKU 可新增多条供应商关系；供应商关系按“SKU + 供应商”唯一，重复绑定时不新增重复记录。
2. 每条供应商关系维护：供应商编码、供应商名称、供应商料号、采购周期（天数）、最小起订量、采购员。
3. 供应商编码、供应商名称、采购员由所关联的供应商资料带出，只读展示；采购员不可在 SKU 页面手工编辑。
4. 一个 SKU 同时只能有一个默认供应商。用户设置某条供应商关系为默认后，系统自动取消原默认标识。
5. 删除供应商关系需二次确认；删除默认供应商后，是否自动将其他关系设为默认，见“待确认问题”。
6. 历史采购单、库存及操作日志保留当时关联的供应商快照，不因后续解除绑定而改写。

### 6.4 批量编辑与导入修改

1. “批量编辑”无需预先勾选 SKU 即可打开；如已勾选 SKU，系统自动带入目标 SKU。
2. 手工修改支持以下基本信息字段：关联 SPU、配货类型、型号、识别码、产品系列、品牌、新品/老品、销售状态、一级类别、二级类别、单位、产品负责人。
3. 手工修改不支持修改中文品名、英文品名、产品类型，以及报关与物流信息；未填写或选择“不修改”的字段保持原值。
4. 导入修改与手工修改位于同一弹窗的两个 Tab 中。导入页复用统一的“下载模板 → 选择文件 → 确认导入”交互，切换 Tab 不改变外层弹窗。
5. 导入模板仅包含本节允许批量修改的字段。校验失败时指出具体行、字段和原因，整批不写入无效数据。

### 6.5 推送至易仓与领星

#### 6.5.1 入口与发起规则

1. 产品列表操作区在“导出”后提供“推送产品”下拉按钮。
2. 下拉项固定为：**推送给易仓**、**推送给领星**、**同时推送给易仓和领星**。
3. 用户必须至少勾选一个 SKU 才能发起推送；未勾选时提示“请先选择需要推送的产品”。
4. 点击某个推送项后，打开推送进度弹窗。弹窗仅展示本次选中的 SKU 和本次目标系统。

#### 6.5.2 推送进度弹窗

| 区域 | 内容与规则 |
|---|---|
| 标题 | 根据目标显示“推送产品至易仓”“推送产品至领星”或“推送产品至易仓和领星”。 |
| 汇总区 | 分别展示待推送、推送中、成功、失败数量。 |
| 任务列表 | 展示 SKU、产品信息、推送目标、推送状态、推送结果。选择同时推送时，同一 SKU 分别展示易仓和领星的状态。 |
| 底部操作 | 任务未开始时提供“开始推送”；执行中显示进度；全部完成后可关闭；存在失败任务时提供“重试失败项”。 |

1. 推送任务按 `SKU + 目标系统 + 本次任务批次` 记录，保证易仓和领星的结果互不覆盖。
2. 同一条任务在“推送中”期间不得重复提交。
3. 目标 ERP 返回业务校验失败时，保留目标系统返回的可展示失败原因；网络超时或未知错误时记录系统错误信息，并标记为失败。
4. “同时推送”中一个目标成功、另一个目标失败时，成功结果保留，不回滚；用户仅重试失败目标。
5. 关闭进度弹窗不取消已开始的推送任务。用户再次进入推送记录时，应能看到任务最终结果；入口和展示位置见待确认问题。

## 七、数据与字段规则

### 7.1 核心数据对象

| 数据对象 | 唯一标识 / 关系 | 说明 |
|---|---|---|
| SKU 主数据 | 中台 SKU | 中台保存的产品主档，是本次维护与推送的来源。 |
| SKU 供应商关系 | SKU + 供应商 | 一条 SKU 可关联多条供应商关系；一个 SKU 最多一个默认供应商。 |
| 推送任务 | 任务批次 + SKU + 目标系统 | 记录推送状态、请求时间、结果、失败原因、重试次数。 |
| 操作日志 | 业务对象 + 操作时间 + 操作人 | 记录新增、编辑、审核、同步四类标准操作类型及可追溯详情。 |

### 7.2 物流属性枚举

物流属性支持多选，枚举值为：普货、含电、纯电、液体、粉末、膏体、带磁、纺织品、木质。

### 7.3 关键字段校验

| 字段 | 校验规则 |
|---|---|
| SKU | 必填；中台 SKU 必须唯一。 |
| 中文品名 | 必填。 |
| 英文品名 | 选填；仅允许英文字符。 |
| 产品类型 | 必填；枚举：单品、组合品。 |
| 配货类型 | 必填；枚举：普货、配件、耗材&辅料。 |
| 品牌 | 必填；单选下拉，支持按既有交互新增枚举值。 |
| 新品/老品 | 选填；枚举：新品、老品、待识别。 |
| 销售状态 | 选填；枚举：新品、常规、在售、清仓、停售、未上市。 |
| 申报价值 | 报关信息中必填；只允许数字输入。 |
| HS code | 不含小数点。 |
| 图片 | 单张不超过 10 MB，单个分类最多 30 张；产品主图和实物图分别管理。 |

## 八、异常与边界场景

| 场景 | 系统处理 | 用户提示 |
|---|---|---|
| SKU 必填项缺失 | 不允许保存，定位缺失字段 | 请完善必填信息 |
| 英文品名包含非英文字符 | 不允许保存 | 品名（英文）仅支持英文输入 |
| 重复关联同一供应商 | 不新增重复关系 | 该供应商已关联当前 SKU |
| 设置默认供应商 | 自动取消原默认供应商 | 已设为默认供应商 |
| 未勾选 SKU 发起推送 | 不创建任务 | 请先选择需要推送的产品 |
| 目标 ERP 校验失败 | 任务标记失败，保留失败原因 | 推送失败：{目标系统返回原因} |
| 同时推送部分失败 | 成功目标保留成功；失败目标允许重试 | {目标系统}推送失败，可重试失败项 |
| 重复点击开始推送 | 同一待执行任务只允许一次提交 | 当前任务正在推送，请勿重复提交 |
| 导入文件格式或数据不合法 | 不写入无效数据，返回行级错误 | 第 {n} 行 {字段}：{原因} |
| 无权限操作 | 前端隐藏入口，后端拒绝请求 | 无此操作权限 |

## 九、系统影响与接口要求

| 系统 / 模块 | 影响内容 | 本次是否处理 |
|---|---|---|
| 中台产品管理 | SKU 主数据统一维护、供应商关系、推送入口与任务记录 | 是 |
| 供应商主数据 | 提供供应商、供应商编码和采购员只读引用 | 是，复用现有主数据 |
| 易仓 ERP | 接收中台发起的 SKU 创建 / 更新请求，并返回处理结果 | 是，需接口联调 |
| 领星 ERP | 接收中台发起的 SKU 创建 / 更新请求，并返回处理结果 | 是，需接口联调 |
| 采购、库存等下游模块 | 读取 SKU 默认供应商或供应商关系 | 需确认具体接入范围 |

接口层须支持请求幂等：同一推送任务重试时，外部系统不得因重复请求生成重复 SKU。接口请求、响应摘要、失败原因、重试次数和完成时间需持久化。

## 十、日志、审计与数据权限

1. SKU 新增、编辑、批量编辑、供应商关系新增 / 删除 / 默认切换、图片变更、导入、推送发起和推送结果均需记录操作日志。
2. 所有功能页面的日志弹窗均使用统一操作类型枚举：**新增、编辑、审核、同步**；不得自行新增或替换操作类型文案。具体业务动作和变更细节写入日志内容。
3. 编辑日志必须逐项记录字段名与变更后的值，格式为“字段名更新为：字段值”；一次修改多个字段时，按字段逐项记录并以中文分号分隔。例如：“销售状态更新为：清仓；产品负责人更新为：张三”。禁止仅记录“更新了字段信息”“更新了基础信息”等无法追溯具体值的描述。
4. 推送日志至少记录：任务批次、SKU、目标系统、请求人、发起时间、请求结果、失败原因、重试次数、完成时间。
5. 供应商关系变更仅影响后续业务选择；历史业务单据保留操作发生时的供应商快照。
6. 用户只能查看其拥有数据范围内的 SKU、供应商关系和推送任务；管理员可查看全部任务及失败原因。

## 十一、验收标准摘要

1. 用户可在一个 SKU 信息弹窗内完成基础信息、尺寸重量、报关与物流、采购信息、关联辅料和图片信息的查看与维护，无需跳转至其他维护页面。
2. SKU 可关联多个供应商；供应商编码、名称和采购员只读带出；同一 SKU 同时只能有一个默认供应商。
3. 已选中 SKU 时，产品列表“推送产品”下拉可选择推送给易仓、推送给领星或同时推送；未选择 SKU 时系统不创建任务并给出明确提示。
4. 推送进度弹窗按 SKU 与目标系统展示待推送、推送中、成功、失败状态和结果；同时推送时，一个目标失败不影响另一个目标的成功结果。
5. 推送失败任务可仅重试失败项，且不会重复执行已成功目标。
6. 保存中台 SKU 后不会自动向外部 ERP 推送；用户需通过产品列表明确发起推送。
7. 供应商关系、SKU 编辑、导入和推送均产生可查看的操作日志；日志可看到操作人和操作时间。编辑日志逐项展示“字段名更新为：字段值”，多项变更用中文分号分隔。
8. 所有功能页面的日志弹窗统一仅使用新增、编辑、审核、同步四类操作类型。
9. 批量编辑仅允许修改已定义的基本信息字段；不得通过批量编辑修改中文品名、英文品名、产品类型、报关与物流信息。
10. 所有页面、弹窗和日志列表遵循现有 [UI 规范](../docs/UI_SPEC.md)，优先复用共享 UI 组件与设计变量。
