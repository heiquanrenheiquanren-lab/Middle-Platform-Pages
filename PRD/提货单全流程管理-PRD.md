## 一、需求背景与定位

### 1.1 背景

现有系统中「提货」不是一个独立单据，而是发货单内部的一个执行动作：发货单处于「待提货」状态时，运营在发货单里点「确认提货」，扣减提货仓库存、增加发货仓库存，单据再流转到「待加工」或「待发货」。

这个设计带来四个问题：

| 问题 | 具体表现 |
|---|---|
| 责任边界模糊 | 提货是采购/仓库去供应商工厂拉货的物理动作，却由运营在发货单里代为点击 |
| 交接凭证缺失 | 提货人、司机、车牌、实提件数、签收人没有载体 |
| 无法对账 | 提货数量散落在发货单明细里，无法与供应商出货单逐单核对 |
| 强绑定 | 货提进来只能服务它所属的那一张发货单，无法跨单调配 |

### 1.2 定位

**提货单是入库单据**：把供应商已完成生产、待我方提货的货物，在提货签收时转入我方库存（自有仓或物流商仓）。

> 注意：提货前这批货在账上**不属于我方存货**，只是供应商仓的待提数量台账。货权、存货、应付、进项都在提货签收这一个时点发生，且只发生一次。详见第七章。

提货单与发货单**平级解耦**：两者不建立单据绑定关系，只通过仓库库存发生关系。

```
入库域：采购单 → 提货单 → 我方自有仓 / 物流商仓
出库域：发货单 → 海外在途 → 目的仓
```

提货单不关心货将来发给谁；发货单不关心货是从哪批采购来的。

### 1.3 适用范围

**仅对以下两家供应商启用提货：JASIC 精密、摩仕达。**

- 这两家供应商存在「货先存放于供应商仓、我方再上门提货」的业务形态。
- 其他供应商无提货概念，采购到货后直接进入采购仓库，走《采购单批量收货》流程，不生成提货单。
- 供应商主数据需新增标记：`是否提货型供应商`。该标记决定采购单详情是否展示「生成提货单」入口，以及供应商库存页是否出现提货入口。

### 1.4 本期不做

- 不处理组合 SKU / BOM 子件拆分提货（提货单不承载加工）。
- 不关联发货单、发货计划。
- 不做提货完成后自动创建发货单。

## 二、单据结构

采用三层结构：**提货单 → 提货批次 → 批次明细**。

不用「单据 + 明细 + 累计已提数量」的两层结构，原因是必须能回答「10 月 8 日那车具体提了什么」——交接凭证、对账、费用分摊都以批次为单位。

### 2.1 单头字段

| 字段 | 说明 | 必填 | 规则 |
|---|---|---|---|
| 提货单号 | `TH + YYYYMMDD + 序号` | 系统生成 | 提交后不可修改 |
| 单据状态 | 见状态机 | 系统维护 | — |
| 供应商 | 仅可选提货型供应商 | 是 | 选定后联动过滤提货仓 |
| 提货仓 | 供应商名下仓库 | 是 | 只能选该供应商的仓库 |
| 目标仓 | 我方自有仓 / 物流商仓 | 是 | 目标仓属性决定后续可用场景 |
| 预计提货日期 | 计划去提货的日期 | 是 | 允许晚于当前日期 |
| 实际首次提货日期 | 首次确认提货时回填 | 否 | 系统写入 |
| 完成日期 | 提满或人工完成时回填 | 否 | 系统写入 |
| 备注 | 最长 200 字 | 否 | — |
| 对账状态 | 未对账 / 部分对账 / 已对账 | 系统维护 | 独立于单据状态 |
| 创建人 / 创建时间 | — | 系统维护 | — |

**单据粒度约束**：一张提货单只能有一个供应商、一个提货仓、一个目标仓。不同仓之间的货必须拆成不同单据。**一张提货单可关联多张采购单**（凑一车），但必须同供应商、同提货仓。

### 2.2 批次字段

| 字段 | 说明 |
|---|---|
| 批次号 | 独立编号，用于头程费用分摊引用 |
| 所属提货单号 | — |
| 提货日期 | 实际提货发生日 |
| 提货人 | 我方跟车/经办人 |
| 司机姓名 / 联系电话 | 承运方信息 |
| 车牌号 | — |
| 运输方式 | 自提 / 供应商送仓 / 第三方物流 |
| 实提总件数 | 批次内明细数量合计，系统汇总 |
| 签收人 / 签收时间 | 目标仓收货确认 |
| 备注 | — |

### 2.3 批次明细字段

| 字段 | 说明 | 规则 |
|---|---|---|
| SKU | — | — |
| 产品名称 | 快照 | — |
| 采购单号 | 来源采购单 | 必填，用于追溯与取价 |
| 采购单行号/序号 | 定位到具体明细行 | 必填 |
| **入库团队** | 货入目标仓后的货权归属团队 | **必填，默认继承采购单行的需求团队**；允许行级修改，修改需记日志。同一提货单可含多个团队 |
| 采购单价 | 从采购单带出 | 只读快照 |
| 采购数量 | 该行采购数量 | 只读 |
| 该行已收货量 | 提货单确认前的采购单累计收货量 | 只读快照 |
| 本次提货数量 | 本批次实提 | 必填，>0 |
| 提货仓 | 默认取单头，允许行级覆盖 | 见 5.3 |
| 差异数量 | `采购数量 − 累计已提` | 系统计算 |
| 差异原因 | 供应商少发 / 货物损坏 / 其他 | 存在差异时必填 |

### 2.4 团队归属规则（Q2 决策）

供应商库存按「SKU + 供应商 + 仓库 + 团队」四维管理，因此货提到我方仓时必须同时落定团队，否则形成无法被发货单引用的无主库存。

| 规则 | 说明 |
|---|---|
| 默认来源 | 继承采购单明细行的需求团队，不需要人工填写 |
| 允许修改 | 提货单明细行可直接修改；用于采购时团队未定、或实际归属发生调整的场景 |
| 粒度 | 按明细行，不按单头。一张提货单可同时含多个团队的货（凑车场景常见） |
| 空值处理 | 采购行团队为空时，提货单对应行必须手工指定，否则不允许提交 |
| 变更留痕 | 手工修改团队需写入操作日志（原团队 → 新团队） |
| 与调拨区分 | 提货入仓后的团队再调整，属于《供应商库存货权调整》范畴，不在提货单内做二次变更 |

## 三、状态机

### 3.1 执行状态（主状态）

```
草稿 ──提交──> 待提货 ──确认提货──> 部分提货 ──提满──> 已完成
  │                │                   │
  └──作废──> 已作废  └──取消──> 已取消   └──（不允许取消）
```

| 状态 | 含义 | 库存影响 |
|---|---|---|
| 草稿 | 已创建未提交 | 无 |
| 待提货 | 已提交，尚未发生实物提货 | 无（仅锁定可提量） |
| 部分提货 | 已发生至少 1 个批次，累计已提 < 应提 | 每批次确认时变动 |
| 已完成 | 提满或人工确认完成 | — |
| 已作废 | 草稿阶段作废 | 无 |
| 已取消 | 待提货阶段取消 | 无 |

状态规则：

1. 仅「草稿」可编辑、可删除、可作废。
2. 仅「草稿」可提交；提交后进入「待提货」，同时锁定各行可提量。
3. 「待提货」「部分提货」可继续提货，每次生成一个批次。
4. 「部分提货」不允许取消——已发生库存变动，需通过提货数量调整或反向单据处理。
5. 「已完成」「已作废」「已取消」为终态，不可编辑、不可重新提交。
6. 完成条件：累计已提数量 = 应提数量，自动完成；或人工确认完成（需填写剩余未提原因）。

### 3.2 对账状态（独立轴）

```
未对账 ──> 部分对账 ──> 已对账
```

对账状态与执行状态互不影响。允许出现「已完成 + 未对账」「部分提货 + 部分对账」等组合。二者不得合并为单一状态字段。

## 四、数量规则

### 4.1 提货数量上限

单行本次可提数量 = `min(采购单该行剩余可提量, 提货仓该 SKU 当前可用量)`

其中：

- 采购单该行剩余可提量 = `采购数量 − 该行累计已提数量`
- 提货仓可用量 = 供应商仓该 SKU 在库量 − 已被其他待提货单锁定数量

**不允许超过采购数量**，超出部分无法入账。

### 4.2 默认值

- 新建时按 `min(剩余可提量, 提货仓可用量)` 自动填充。
- 提供「按上限填充」按钮，一键填充当前全部行。

### 4.3 差异

- 差异数量 = `采购数量 − 累计已提数量`，仅在单据完成时结算。
- 差异必须选择原因：供应商少发 / 货物损坏 / 其他（选「其他」必须填备注）。
- 差异不回退采购单数量，仅在提货单留存记录，供采购与供应商交涉。

## 五、库存规则

### 5.1 时点

| 动作 | 库存影响 |
|---|---|
| 创建草稿 | 无 |
| 提交 | 无实际扣减，但锁定可提量（软占用），防止两单抢同一批货 |
| 确认提货（生成批次） | 扣减提货仓该 SKU 在库量；增加目标仓该 SKU 在库量；**同步回写采购单该行累计收货量与收货状态** |
| 取消（待提货） | 释放锁定量，无库存变动，无采购回写 |
| 作废（草稿） | 释放锁定量，无库存变动，无采购回写 |

三个动作必须落在同一事务内：**生成提货批次 + 目标仓入库（按入库团队）+ 采购单收货回写**。任一步失败则整体回滚，不允许出现「库存动了但采购没回写」或「采购回写了但库存没动」。

### 5.2 目标仓差异

- **入物流商仓**：库存进入该物流商对应发货仓，可直接被发货单引用。
- **入自有仓**：库存进入自有仓，后续需通过调拨单转入物流商仓才可发货。
- 物流商与发货仓一一对应，不得混用（沿用 2026-08-20 提货规则讨论结论）。

### 5.3 行级提货仓

单头已限定供应商，但同一供应商可能有多个提货仓。允许在明细行覆盖提货仓，前提是仍属于该供应商名下仓库。若某行提货仓与单头不同，系统需在批次中记录实际提货仓。

### 5.4 入库落点：不得落入供应商仓

**规则：提货回写采购收货时，入库流水必须落在「实际收货仓」（提货单签收的目标仓），不得落在采购单头填写的供应商仓。**

这条规则来自现状中一个具体的字段错位：采购单的「采购仓库」填的是 JASIC 精密一厂、摩仕达东莞仓这类供应商仓，而采购单收货在本系统中就是入库动作（填写收货数量、生成收货批次、增加库存）。由于收货批次本身不携带仓库字段，入库流水只能继承采购单头，于是货已被提至中转仓、账却仍挂在供应商仓。

入库不能入供应商仓，四个层面的理由：

1. **控制权**：供应商仓不是我方仓库。我方不持有出入库控制权、不派驻人员管理、不承担保管责任，货物毁损灭失的风险也不由我方承担。把它当作我方库存入账，等于替供应商保管货物却记成我方资产。
2. **账实不符**：提货装车后货物已离开供应商仓。此时盘点供应商仓，这批货一件也找不到，但账上仍挂着数百件库存。这是审计必然发现的账实差异。
3. **存货存在性无法证明**：报表的「存货」中会出现一批存放于第三方工厂的货物，既无仓储保管协议，也无盘点记录覆盖。在财务上属于无法验证存在性的资产，期末审计无法出具结论。
4. **下游流程会卡死**：发货单需要从物流中转仓扣减库存，但库存被记在供应商仓，扣减失败，发货单无法推进。

落地约束：

| 项 | 规则 |
|---|---|
| 收货仓库字段 | 采购单收货批次需记录「收货仓库」，默认取提货单签收的目标仓 |
| 可选范围 | 收货仓库不得选择供应商仓；供应商仓不属于我方实体仓，不参与库存核算 |
| 字段语义 | 采购单头「采购仓库」只表示提货来源仓，不承担收货入库仓的语义，历史数据不改 |
| 存量处理 | 若供应商仓在仓库主数据中已有库存余额，说明历史入库已落错仓，需先做库存结转再上线本规则 |

本条与 6.2「提货即收货」互为一体：既然提货时同步完成采购收货，那么这一次入库就必须落在货实际到达的仓，否则提货、入库、采购收货三者会在仓库维度上错位。

## 六、与采购单的关系

### 6.1 关联方式

- 提货单必须从采购单下推生成，或新建时通过「选择采购单」带入明细。
- 可选的采购单范围：状态为「待收货」「部分收货」且供应商为提货型供应商。
- 一张采购单可被多张提货单引用（分批提货）；一张提货单也可引用多张采购单（凑车）。
- 采购单反查：采购单详情展示「已生成提货单」及累计已提数量。

### 6.2 采购收货的处理（Q1 决策：采用 A 方案——提货即收货）

**结论：提货批次确认时，同步回写采购单该行累计收货量 +本次提货量。**

理由：

1. 提货是实物从供应商仓进入我方仓的唯一动作，货已在手，采购单不存在「未收货」状态。
2. 现状是采购员看着提货记录手工到采购单再收一遍，属于纯重复录入，且金额、数量容易抄错。
3. 不回写会导致采购单长期挂「部分收货」，采购结账与供应商对账都无法收敛。

回写规则：

| 项 | 规则 |
|---|---|
| 触发时点 | 每次「确认提货」生成批次时，按批次明细逐行回写 |
| 回写字段 | 采购单行累计收货量 `+= 本次提货数量`；供应商仓可用量 `−= 本次提货数量` |
| 幂等 | 以提货批次为最小回写单元，同一批次不重复回写；提货单取消（未提货）不产生回写 |
| 部分提货 | 每次提货独立回写，采购单状态随累计收货量自动流转：未收货 → 部分收货 → 已收货 |
| 收完判断 | 累计收货量 ≥ 采购数量时，采购单行置为「已收完」，不可再被提货单选入 |
| 差异处理 | 少提形成的差异不回退采购数量，采购单保持「部分收货」，由采购员走采购变更或关闭行处理 |
| 操作入口 | 提货型供应商的采购单**关闭人工收货入口**，避免与提货回写重复 |

对应地，非提货型供应商的采购单仍走《采购单批量收货》，两者按供应商标记分流。

## 七、账务与税务处理

### 7.1 三条流必须先拆开

「提货时到底先入他们的库还是先提走」这个问法，把三件事混成了一件。实际业务里它们是三条独立的线，可以不同步，但必须能对上。

| 流 | 关键节点 | 谁在动 |
|---|---|---|
| 物理流 | 供应商产线 → 供应商仓 → 装车提货 → 我方仓/物流仓 | 供应商、承运人、仓库 |
| 货权流 | 提货签收时，货物控制权与毁损风险转移至我方 | 由合同条款约定 |
| 账务流 | 提货签收时，存货与应付同时确认；提货前不入账 | 财务 |
| 票据流 | 供应商按提货量开票；我方取得专票后抵扣进项 | 供应商、税务 |

### 7.2 系统现状与账务口径的对齐

采购单的「采购仓库」指向 JASIC 精密一厂/二厂、摩仕达东莞仓，其含义是**提货来源仓**，不是「已完成收货的仓库」。6.2 已确定提货时才回写采购收货，因此在系统里提货前采购单处于「待收货」，没有产生任何入库动作。

结论：**系统里只有一次入库，就是提货。不存在「先入供应商仓库存、再提走」这个账务环节。**

供应商仓的库存只做数量台账（备查簿），用途是回答「还有多少没提」，不进入存货科目，不产生应付。

### 7.3 选定口径：提货签收 = 交易完成节点

| 环节 | 账务动作 | 是否产生应付 |
|---|---|---|
| 采购下单 | 无（预付除外，挂预付账款） | 否 |
| 货在供应商仓待提 | 仅数量台账备查，不入存货 | 否 |
| **提货签收** | **确认存货 + 应付 + 进项** | **是，唯一一次** |
| 入仓后调拨/加工 | 存货科目内部转移，金额不变 | 否 |
| 对账开票 | 冲暂估、确认进项 | 否 |
| 付款 | 冲减应付 | 否 |

选这个口径的三条依据：

1. **增值税**：《中华人民共和国增值税法》第二十八条（2026-01-01 施行）规定纳税义务发生时间为收讫销售款项或取得索取销售款项凭据的当日；《实施条例》第三十九条进一步明确，未约定付款日期的，为应税交易完成当日，即**货物发出**当日。提货放行才是货物发出，提货前的账面入账没有对应的纳税义务，会和供应商开票节奏脱节。
2. **会计**：存货确认以控制权转移为准。提货前货在供应商厂区，我方需供应商放行才能处置，也无法阻止其挪用，控制权并未完全转移。
3. **三流一致**：提货单天然是「合同流—货物流—票据流」的交叉点，一张单同时承担入库单（GRN）、交接凭证、对账依据三个角色，证据链最短。

### 7.4 会计处理

**场景一：先提货、后收票（最常见）**

```text
1) 提货签收，发票未到，按采购单价暂估
   借：库存商品—XX仓（暂估，不含税）
     贷：应付账款—暂估应付款

2) 发票到达，先红冲暂估，再按票入账
   借：库存商品—XX仓（红字，冲暂估）
     贷：应付账款—暂估应付款（红字）
   借：库存商品—XX仓
       应交税费—应交增值税（进项税额）
     贷：应付账款—供应商

3) 付款
   借：应付账款—供应商
     贷：银行存款
```

**场景二：预付货款后提货**

```text
1) 预付
   借：预付账款
     贷：银行存款
2) 提货签收并收票
   借：库存商品
       应交税费—应交增值税（进项税额）
     贷：预付账款
         应付账款（差额部分）
```

**场景三：我方自提，运费直接付给承运人**

```text
   借：库存商品（采购价 + 运费，运费计入存货成本）
       应交税费—应交增值税（进项税额，货物 13% + 运输 9%）
     贷：应付账款—供应商
         银行存款（运费）
```

运费计入存货成本，随销售结转，不在当期一次性进费用——这一条直接影响毛利率，务必和财务对齐。

### 7.5 备选口径：先入账后提货（占有改定）

只有在合同强制要求、且供应商愿意配合时才启用。

启用前提（缺一不可）：

1. 合同明确约定「货物在供应商仓验收即视为交付，供应商继续占有但货权归我方」（占有改定）；
2. 供应商按**收货量**而非提货量开票；
3. 双方签订仓储保管协议，明确保管责任、毁损承担与盘点机制；
4. 我方存货盘点范围能覆盖供应商仓，或每期取得供应商盖章的库存证明。

四个风险，需要书面告知财务与审计：

| 风险 | 说明 |
|---|---|
| 物权风险 | 占有改定不能对抗善意第三人。供应商破产、被查封或一货多卖时，我方可能无法取回货物 |
| 税会差异 | 供应商实际多按提货开票，会导致长期「暂估入库」、进项滞后，需要单独的差异台账 |
| 审计质疑 | 账面存货存放在供应商处，存在性无法验证，审计可能要求函证甚至调整 |
| 指标失真 | 期末存货虚高，存货周转率、毛利率都会被拉低或扭曲 |

**结论**：除非合同与供应商都能配合，否则不采用。推荐 7.3 的口径。

### 7.6 税务处理要点

| 事项 | 处理口径 | 注意 |
|---|---|---|
| 供应商开票时点 | 按提货放行（货物发出），与合同付款日孰先 | 增值税法第 28 条；先开票的，为开票当日 |
| 我方进项抵扣 | 取得合规专票即可抵扣，与是否付款无关 | 发票品名、数量、金额须与提货单一致，否则作进项转出 |
| 运费（供应商收取） | 属**价外费用**，并入货物销售额按 13% 开票 | 常见错误：供应商按 9% 运输服务开票，我方按运输抵扣，属凭证不合规 |
| 运费（我方直付承运人） | 承运人开 9% 运输服务专票，计入存货成本 | 合同主体、付款主体、发票抬头必须一致 |
| 仓储费 | 6% 仓储服务；入库前发生的可计入存货成本，入库后计当期损益 | 须单独开票，不得混入货物价款按 13% 开 |
| 提货短少 / 破损 | 供应商责任：索赔或红字发票冲减；管理不善：进项税额转出 | 合理途耗计入存货成本，不作损失 |
| 质量扣款 | 由供应商开红字发票冲减采购额与进项 | 不得只冲应付不开红字，会造成进项虚抵 |
| 退货 | 红字发票 + 反向入库 | 与提货单关联，保留批次追溯 |

### 7.7 合同条款建议

| 条款 | 建议表述 |
|---|---|
| 交货地点 | 供应商仓库（JASIC 精密一厂/二厂、摩仕达东莞仓） |
| 交货方式 | 我方或我方指定承运人自提，以提货签收为交付完成 |
| 风险转移 | 自提货签收时起转移至我方 |
| 所有权转移 | 与风险转移同步（不建议设所有权保留，会影响我方入账与融资） |
| 计量依据 | 以我方提货签收数量为准；差异应在提货后 3 个工作日内提出 |
| 结算依据 | 按月对账，以提货单为对账依据，对账确认后开票 |
| 保管责任 | 提货前货物由供应商保管，毁损、丢失由供应商承担 |
| 运输 | 明确谁承运、运费谁承担、发票开给谁 |

### 7.8 附：待讨论方案辨析——供应商仓过账

> 本节为业务讨论素材，**不是推荐方案**。业务方曾提出下述做法，需要与财务、审计共同判断是否成立。

#### 7.8.1 方案描述

向供应商仓提货 100 件，实际到达物流中转仓清点为 99 件。提出如下三步库存处理：

```
供应商仓 +99（入库）
供应商仓 −99（出库）
中转仓   +99（入库）
```

即：先按实际到货数量完成采购入库，再以提货为出库动作减掉，同时给中转仓增加库存。

#### 7.8.2 三笔流水的净额为零

供应商仓一进一出，净额为零。这个方案绕了一圈，实际得到的与「直接入中转仓」完全一致，只是多产生两条流水。

| 对比项 | 三步过账方案 | 直接入中转仓 |
|---|---|---|
| 存货总额 | +99 | +99 |
| 应付账款 | +99 × 单价 | +99 × 单价 |
| 进项税额 | 一致 | 一致 |
| 采购单收货量 | +99 | +99 |
| 库存流水条数 | **3 条** | **1 条** |
| 供应商仓余额 | 提货前后均为 0 | 提货前后均为 0 |

表的最后两行是关键：**供应商仓的余额在两套方案中均为零**，因为该设计是「入完立即出」。既然结果恒为零，这两条流水存在的唯一理由，是让采购单头的「采购仓库 = 供应商仓」看起来与收货入库仓一致。

**这属于迁就字段，而非修正字段。**

#### 7.8.3 方案内含的矛盾：货权时点二选一

`+99` 与 `−99` 发生在同一瞬间，意味着货权在提货之前并未转移给到我方。若货权早已转移，供应商仓的余额在提货前就应是 99，不需要等到签收那一刻才出现。

| 情况 | 事实 | 后果 |
|---|---|---|
| 货权提货前未转移 | 该 `+99` 是虚拟的，余额凭空产生 | 审计会认定为过账（用流水把余额做平），属账务处理不当 |
| 货权提货前已转移 | 应在「生产完成、入供应商仓」时即 `+99` 并挂应付 | 提货时仅剩仓间调拨（供应商仓 −99、中转仓 +99），不再产生应付 |

**两个选项互斥。不能既要一个临时的 `+99`，又不承认货权提前转移。只要那个临时 `+99` 存在，它就是虚的。**

#### 7.8.4 审计视角的三个必问

审计抽到这张提货单，会看到三条库存流水：同一仓一进一出、另一仓一进。三个问题必然被问：

1. **「JASIC 精密一厂」是否为我方仓库？** 若是，租赁协议、保管合同、保险凭证在哪？若不是，凭什么在我方库存流水中记录其进出？
2. **为什么要在供应商仓过一手？** 若答「因为采购单头填的是这个仓」，等于承认该字段使用错误，审计会顺着追查采购单与入库单的对应关系。
3. **`+99` 那一刻，存货是否虚增？** 若三笔不在同一事务、同一时点，月末结账恰好卡在中间，存货将多计 99 件的金额。

第 3 条在实操中最易出问题：系统中三笔流水通常分属三个事务，中间只要一笔失败或跨天，就会残留「供应商仓有 99 件货」的状态，且难以被发现。

#### 7.8.5 该方案成立的前提

存在一种情形下该方案不但可行，而且是标准做法：**供应商仓实质上是我方存货的存放地。** 例如在供应商厂内租用专属库位并自行保管、VMI／寄售模式且货权在生产完成时即转移、已签署仓储保管协议且盘点覆盖该仓。

此时「采购入库至供应商仓 → 内部调拨至中转仓」是标准处理。但必须同步修正一点：`+99` 要提前到「货权转移」那一刻，不能在提货签收时才做；否则中间月份存货少计、次月多计。

#### 7.8.6 判断线

**向财务确认：这两家供应商仓的货，当前是否计入资产负债表的「存货」。**

- **计入** → 方案成立。需同时补齐：提前入账、仓储保管协议、盘点覆盖该仓、单据类型命名为「库位转移／内部调拨」而非「采购入库」。
- **未计入** → 方案不成立，第一步即为虚构。正确做法只有一条：收货时指定实际收货仓为中转仓，采购单头的「采购仓库」仅表示提货来源。

#### 7.8.7 若最终确定采用，五项硬约束

| 约束 | 要求 |
|---|---|
| 同一事务 | 三笔流水必须同一事务、同一时点，不允许分次提交 |
| 入账时点 | `+99` 只能在货权真实转移时发生，不得事后补记 |
| 单据命名 | 不得命名「采购入库」，应为「采购入库（供应商仓暂存）」+「库位转移」，使审计可识别为两件事 |
| 仓储协议 | 必须有书面保管协议，明确保管责任与盘点安排 |
| 盘点覆盖 | 期末盘点须覆盖供应商仓，否则存货存在性仍无法证明 |

#### 7.8.8 业务讨论提纲

| 编号 | 待讨论问题 | 需谁回答 |
|---|---|---|
| D1 | 两家供应商仓的货，当前是否计入我方存货科目？ | 财务 |
| D2 | 若计入，货权转移时点的合同依据是什么？ | 采购／法务 |
| D3 | 供应商仓是否有书面保管协议、是否纳入期末盘点？ | 财务／仓储 |
| D4 | 若不计入，采购单「采购仓库」字段是否可改语义或新增「收货仓库」？ | 产品／研发 |
| D5 | 三条流水的实现是否在同一事务内？失败补偿机制如何设计？ | 研发 |

## 八、对账与三单匹配

### 8.1 对账对象与周期

- 对账对象：**供应商**，核对数量与金额。
- 本期不做货代提货费对账（见 Q5）。
- 周期：按月，按**提货日期**归属期间，不按创建日期。

### 8.2 对账单要素

| 分类 | 字段 |
|---|---|
| 基本信息 | 对账单号、供应商、对账期间、币种 |
| 期初 | 期初未提数量、期初未结金额 |
| 本期发生 | 提货单号、提货批次号、供应商出货单号、提货日期、SKU、数量、单价、金额 |
| 本期调整 | 退货数量、索赔金额、折让 |
| 期末 | 期末未提数量、期末应付金额 |
| 差异 | 数量差、金额差、差异原因、处理方式 |
| 确认 | 我方对账人、供应商确认人、确认时间、对账单附件 |

### 8.3 差异处理

| 差异类型 | 处理方式 | 单据动作 |
|---|---|---|
| 供应商少发 | 补发或按实提数量结算 | 冲减应付；采购单差异数量保留，走采购变更或关闭行 |
| 货物破损 | 供应商换货或索赔 | 生成索赔单，冲减应付或收取赔款 |
| 错发 SKU | 退回或协商转用 | 红字发票 + 反向入库 |
| 单价不一致 | 以采购单单价为准 | 差异挂起，不进入付款 |
| 发票金额与对账单不一致 | 退回重开 | 三单匹配不通过，挂「待处理」 |

### 8.4 三单匹配

这是财务合规的核心控制点，也是「提货单能不能替代入库单」的答案——能，它就是 GRN。

| 单据 | 角色 | 匹配字段 |
|---|---|---|
| 采购单（PO） | 价格与订购基准 | 供应商、SKU、单价、订购数量 |
| 提货单（GRN） | 实收依据 | 实提数量、提货日期、批次号 |
| 发票（Invoice） | 计税凭证 | 数量、单价、金额、税率、税额 |

匹配规则：

1. 提货数量 ≤ 采购单该行剩余可收数量；
2. 发票单价 = 采购单单价（容差 0，有差异须走采购变更）；
3. 发票金额 = 提货数量 × 单价，税额 = 金额 × 税率；
4. 三项全部通过才允许进入付款流程；任一项不通过，单据挂「匹配不通过」，财务不得手工放行。

### 8.5 对账状态流转

- 未对账：批次尚未纳入任何对账周期
- 部分对账：单据内部分批次已对账
- 已对账：全部批次已对账
- 差异挂账：已对账但存在未处理差异（与对账状态并行，不覆盖）

| 9 | 「选择采购单」弹窗 | 只显示数量 | 增加**已收货 / 剩余可提 / 收货状态**三列；已收完的行置灰不可选 |
| 10 | 详情弹窗 | 「库存转移记录」为扁平日志 | 升级为「提货批次」独立区块，展示批次号/日期/提货人/司机车牌/运输方式/件数/签收人 |
| 11 | 详情弹窗 | 无对账明细 | 新增对账区块：对账状态/已对账数量/未对账数量/货值 |
| 12 | 详情弹窗 | 无采购回写记录 | 新增「采购单回写」区块：采购单号/SKU/本批回写/回写前已收/回写后已收/收货状态/提货批次/时间 |
| 13 | 新建弹窗 | 直接列 SKU 清单 | 改为「选择采购单」弹窗带入明细，支持按上限填充 |
| 14 | 提货弹窗 | 只有数量输入 | 表格增加采购单号、入库团队；增加批次交接信息；底部实时显示回写预览与「回写采购单 N 张」 |
| 15 | 提交动作 | 「提交」与「保存草稿」行为相同 | 修复：提交后状态进入「待提货」（原缺陷） |

数据模型同步调整为「提货单 → 提货批次 → 批次明细」三层，移除全部发货单、发货计划、组合件相关字段。

注意：原型中提货确认后同时更新了内存中的采购池数据，因而回写效果可在「选择采购单」弹窗中直接观察到（已收完的采购行变为不可选）。真实系统需由后端保证回写事务与幂等。

### 9.2 按第七章口径，原型还需补的对账字段

当前原型只有「对账状态 / 已对账数量 / 未对账数量 / 货值」，属于标记级，不足以支撑 8.4 的三单匹配。需补：

| 位置 | 新增字段 | 说明 |
|---|---|---|
| 提货批次 | 供应商出货单号 | 与供应商出库单逐笔勾稽的依据 |
| 提货批次 | 对账期间 | YYYY-MM，按提货日期归属 |
| 对账区块 | 发票号 / 开票日期 / 发票金额 / 税额 | 发票登记，支撑进项核对 |
| 对账区块 | 三单匹配状态 | 待匹配 / 匹配通过 / 匹配不通过（含不通过原因） |
| 对账区块 | 差异数量 / 差异金额 / 差异原因 / 处理方式 | 差异必须可追溯，且不能与对账状态混为一个字段 |
| 详情 | 运费承担方式 / 运费金额 / 运费发票类型 | 区分 13% 价外费用与 9% 运输服务 |

这些字段不建议直接塞进现有列表页，应放在详情页的对账区块，或独立成「供应商对账单」单据按期间生成。

## 十、决策记录与待确认问题

### 10.1 已决策（2026-10-31）

| 编号 | 问题 | 结论 | 落点 |
|---|---|---|---|
| Q1 | 提货完成后是否回写采购单收货？ | **回写**。提货即收货，按批次逐行增加采购单累计收货量；提货型供应商关闭采购单人工收货入口 | 见 6.2；原型已在确认提货时回写并展示回写明细 |
| Q2 | 提货后货权归属团队如何确定？ | **明细行新增「入库团队」字段**，默认继承采购单行团队，允许行级修改并留痕；一张单可含多团队 | 见 2.4；原型明细行、选择采购单、确认提货、列表、详情均已落地 |
| Q8 | 账务上在哪一个时点确认存货与应付？ | **提货签收时点，仅一次**。提货前供应商仓只做数量台账、不入存货、不挂应付；提货后再无新增应付 | 见第七章 |

### 10.2 仍待确认

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| Q3 | 提货仓可用量的口径是什么？ | 是「采购已下单未提货量」，还是供应商仓的独立盘点数？两者会有差异（供应商少发、货物损坏） | 建议以独立库存台账为准，采购未提量只作为参考上限；若两者长期不一致，说明供应商报数不准，需对账校准 |
| Q4 | 是否允许一张提货单跨多张采购单？ | 影响单头校验与列表展示 | 建议允许（凑车），但限同供应商同提货仓（原型已按此实现） |
| Q5 | 对账是否含金额？单价取采购单单价还是提货时另行维护？ | 影响对账字段与财务口径 | 建议取采购单单价快照；本期只做供应商对账，不做货代提货费对账 |
| Q6 | 部分提货后如何取消？ | 已发生库存变动，直接取消会导致账实不符 | 建议通过「提货数量调整」减量，或走反向入库单 |

| Q9 | 这两家供应商的结算方式与开票时点是什么？ | 决定是否存在预付账款、账期从提货日还是对账日起算、供应商是否按提货量开票 | 需逐个供应商确认：月结 30/90/150/180 天，还是款到发货（预款 20%/30%）。若为款到发货，提货前已有资金流出，但存货与应付仍应在提货时确认，差额挂预付账款 |
| Q10 | 自提运费由谁承担、发票开给谁？ | 决定运费是 13% 价外费用还是 9% 运输服务，直接影响进项抵扣合规性 | 建议我方直接与承运人签约并付款，取得 9% 运输专票计入存货成本；若由供应商代运，须并入货物价款按 13% 开票 |
| Q11 | 供应商仓的待提货是否纳入我方存货盘点？ | 若采用 7.5 占有改定口径则必须纳入；若采用 7.3 口径则无需 | 建议采用 7.3，仅做数量台账，每季度与供应商核对一次待提数量 |

## 十一、口径变更的影响面

本次确定账务口径后，以下文档的表述需要同步，否则联调时会出现两套说法：

| 文档 | 需要改的地方 |
|---|---|
| `docs/BUSINESS_LOGIC.md` 第 57 行 | 「采购在途 → 供应商仓库存」应拆为「采购在途 → 待提数量（备查）→ 提货入库」，避免被理解为供应商仓库存是我方存货 |
| 本 PRD 1.2 | 已修正（本次） |
| 《供应商库存货权调整-PRD》 | 需说明该页面的「在库量」在提货完成前属于待提台账，不是可核算存货；否则团队间货权调整会调走尚未入账的货 |
| 《采购单批量收货-PRD》 | 需说明提货型供应商不走批量收货，由提货回写驱动 |
