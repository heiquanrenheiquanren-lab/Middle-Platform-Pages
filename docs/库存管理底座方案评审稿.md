# 库存管理底座方案评审稿

> 文档状态：方案评审稿  
> 适用范围：供应链中台 2.0 库存管理底座  
> 评审对象：供应链、采购、运营、财务/成本、产品、研发、测试

---

## 一、评审目标

本次评审先确认库存底层规则，不展开页面和技术实现细节，重点统一以下内容：

1. 哪些业务动作会导致库存入库或出库；
2. 在库、占用、冻结、可用、在途等数量的含义和计算关系；
3. 一份库存由哪些维度共同确定；
4. 批次、库龄和成本如何记录与扣减；
5. 哪些单据会占用库存，单据结束后如何释放；
6. 如何通过库存余额、库存流水和占用明细追溯库存变化。

评审通过后，采购、发货、加工、调拨、退货和盘点统一使用该库存底座，不再分别维护不同库存口径。

---

## 二、现状与核心问题

### 2.1 当前已知问题

1. 物理库存曾同时包含 SKU、仓库、团队、平台、店铺、Seller SKU，库存归属和销售属性混在一起，容易重复统计或人为拆分库存。
2. “在库量”“在库（待发）量”“在途/在产量”“总量”等字段关系不清晰，不同部门理解不一致。
3. 缺少完整的库存占用和释放机制，业务单据完成后可能残留无效占用。
4. 批次、库龄、成本和来源单据之间缺少统一关联。
5. 缺少完整库存流水时，无法解释库存为什么增加、减少或从 100 变成 99。
6. 海外仓、FBA、供应商仓的数据来源和更新频率不同，中台库存可能与外部实物库存存在差异。

### 2.2 当前已确认或已有规划的业务方向

1. 物理库存核心颗粒度收敛为 `SKU + 仓库 + 团队/货主`，平台、店铺、Seller SKU 不作为物理库存主维度。
2. eBay、Shopee 等非 Amazon 平台，同一团队内多个店铺可以共享库存。
3. Amazon 不同店铺不能默认共享库存，需要通过店铺独占库存范围控制。
4. 库内加工在同一仓库、同一团队范围消耗子件，按入库批次先进先出，并生成新的加工批次和成品库存。
5. 所有库存变化必须由业务动作产生，并留下可追溯记录。

### 2.3 本方案框架

```text
库存中心
├─ 出入库类型
├─ 库存数量与状态
├─ 库存颗粒度
├─ 批次、库龄与成本
├─ 库存占用与释放
└─ 库存账本与追溯（三本账）
```

## 三、出入库类型

### 3.1 入库类型

| 入库类型 | 触发场景 | 主要库存变化 |
|---|---|---|
| 采购入库 | 采购收货完成 | 增加在库，生成采购入库批次 |
| 加工入库 | 组合成品加工完成 | 增加成品在库，生成加工批次 |
| 调拨入库 | 调拨货物到达目标仓 | 减少调拨在途，增加目标仓在库 |
| 盘盈入库 | 实盘数量大于账面数量 | 增加在库，生成盘盈批次 |
| 退货入库 | 非销售类退回库存 | 先进入待确认，确认后转为可用或不良 |
| 赠品入库 | 无采购成本或特殊来源的赠品 | 增加在库，记录来源和成本规则 |
| 销售退件入库 | 客户或平台退件到仓 | 先进入待确认，确认后转为可用或不良 |

### 3.2 出库类型

| 出库类型 | 触发场景 | 主要库存变化 |
|---|---|---|
| 加工出库 | 子件投入库内加工 | 扣减子件在库，按批次消耗 |
| 销售出库 | 销售订单或发货单实际出库 | 扣减在库，同时结算占用 |
| 采购退货出库（建议） | 退回供应商 | 扣减在库 |
| 调拨出库（建议） | 从源仓发往目标仓 | 扣减源仓在库，增加调拨在途 |
| 盘亏出库（建议） | 实盘数量小于账面数量 | 扣减在库 |
| 其他调整出库（建议） | 特殊纠错 | 扣减在库，必须填写原因并限制权限 |
| 报损出库 | 破损、丢失或报废 | 扣减对应状态库存 |

### 3.3 基本原则

1. 没有明确出入库类型，不允许直接增加或扣减库存。
2. 出入库类型用于说明库存如何变化，来源单据用于说明为什么变化。
3. 不允许直接修改库存余额；盘点差异、数据纠错也必须通过盘盈、盘亏或调整单产生流水。
4. 单据冲销不能删除原记录，应生成反向库存流水。

### 3.4 主要业务流转

| 业务动作 | 流转关系 |
|---|---|
| 采购入库 | 采购在途减少 → 在库增加 |
| 销售出库 | 占用减少 → 在库减少 |
| 调拨 | 源仓在库减少 → 调拨在途增加 → 目标仓在库增加 |
| 加工 | 子件在库减少 → 组合成品在库增加 |
| 退货 | 待确认增加 → 确认后转可用或不良 |
| 盘点 | 形成盘盈或盘亏差异 → 生成对应出入库流水 |

## 四、库存数量与状态

### 4.1 库存状态定义

| 库存状态 | 定义 |
|---|---|
| 在库库存 | 仓库实际存在并已完成入库确认的货 |
| 占用库存 | 已被发货单、加工单、调拨单等业务预留的货 |
| 冻结库存 | 因质量异常、盘点或人工控制暂时不能使用的货 |
| 可用库存 | 当前还能继续被新业务使用的数量 |
| 在途库存 | 已发出但尚未完成目标仓入库的货 |
| 虚拟库存 | 供应商直发等非公司实际在库、但业务上可承诺的供应量 |
| 待确认库存 | 已到货但采购收货、质检或数量尚未确认的货 |

> 如果仍需管理“在产量”，建议将其单独定义，不再与在途量合并。

### 4.2 核心公式

```text
可用量 = 在库量 - 占用量 - 冻结量

库存总量 = 在库量 + 在途量
```

说明：

- 占用量、冻结量是在库量中的受限部分，不能再次计入库存总量；
- 待确认库存未正式入库，不计入在库量；
- 虚拟库存不是公司实物库存，是否参与“可承诺量”需单独确认；
- 供应商直发不建议通过“虚拟入库”增加物理在库量，可作为可承诺供应量单独管理，实际发货后记录履约结果；
- 原“在库（待发）量”建议归入占用库存，在页面上可展示为“发货占用”。

### 4.3 零库存展示

当在库、占用、冻结、待确认、在途及批次剩余量均为 0 时，库存查询默认不展示该记录，但保留历史流水。用户搜索指定 SKU 或开启“显示零库存”后仍可查询。

## 五、库存颗粒度

系统中的一份物理库存由以下维度共同确定：

```text
SKU + 仓库 + 团队/货主
```

说明：

1. SKU 表示是什么货；
2. 仓库表示货在哪里；
3. 团队/货主表示货属于谁；
4. 批次是该库存下的来源明细，不是库存汇总维度；
5. 平台、店铺、Seller SKU、FNSKU 属于销售或外部平台属性，不作为物理库存主维度；
6. 团队共享库存和 Amazon 店铺独占库存，通过库存池或使用范围控制，不重复拆分物理库存；
7. 公共库存不建议用“团队为空”表示，应设置明确的公共货主或公共库存范围。

## 六、批次、库龄与成本

### 6.1 批次核心字段

| 字段 | 说明 |
|---|---|
| 入库批次号 | 每次形成库存时生成的唯一批次编号 |
| SKU、仓库、团队/货主 | 批次对应的库存范围 |
| 来源类型 | 采购、加工、调拨、退货、盘盈、赠品等 |
| 来源单据 | 采购单、加工单、调拨单、退货单等 |
| 入库日期 | 用于计算库龄和先进先出顺序 |
| 批次入库数量 | 本批次最初形成的数量 |
| 批次剩余数量 | 当前仍未被消耗的数量 |
| 批次成本价 | 本批次单位成本 |

### 6.2 批次解决的三个问题

1. 库存从哪里来：什么入库类型、什么单据、谁操作；
2. 出库时先扣哪一批：每一批还剩多少；
3. 成本和库龄怎么计算。

### 6.3 批次生成规则

批次不是采购入库独有。所有形成库存的入库动作都应生成库存批次。

| 场景 | 批次规则 |
|---|---|
| 采购入库 | 每次实际收货生成采购入库批次 |
| 加工入库 | 每次加工完成生成新的成品批次，并关联子件来源批次和 BOM 版本 |
| 调拨入库 | 目标仓生成调拨入库批次，同时保留原始来源批次、成本和库龄信息 |
| 退货入库 | 生成退货批次并关联原销售出库批次 |
| 盘盈/赠品入库 | 生成对应来源批次并记录成本规则 |

占用、释放、冻结、解冻和正常出库不形成新的库存来源，沿用原批次。

### 6.4 批次扣减顺序

默认按入库日期先进先出（FIFO）：

```text
优先扣减最早入库且当前可用的批次
```

若商品涉及有效期，可扩展为按效期优先。

### 6.5 库龄

库龄根据批次入库日期动态计算，不直接维护“0—30日数量”等固定结果，并满足：

```text
在库量 = 各库龄区间数量之和
```

需确认：调拨到新仓后，库龄是继承原始入库日期，还是从调拨入库日期重新计算。

### 6.6 批次成本构成

批次成本价不是只有采购单价。原则上，为使商品达到当前场所和状态、能够合理归属于该批库存的支出，可以进入批次成本。

```text
批次单位成本 =（采购成本 + 可归属运输费 + 可归属加工费
              + 可归属辅料包材费 + 其他可归属入库成本）÷ 批次数量
```

| 成本项目 | 是否进入批次成本 | 说明 |
|---|---|---|
| 采购价款 | 是 | 扣除可抵扣税额后的采购成本口径由财务确认 |
| 入库前运输、装卸、保险等 | 原则上是 | 必须能够合理归属于采购批次 |
| 委外加工费 | 原则上是 | 进入加工后形成的新成品批次成本 |
| 为形成商品所必需的辅料、包材 | 原则上是 | 与销售推广有关的包装费用不当然进入存货成本 |
| 其他入库费 | 视性质判断 | 必须满足“使存货达到当前场所和状态”的条件 |
| 异常损耗、销售费用、管理费用 | 否 | 发生时计入当期损益，不进入批次成本 |

> “成本”用于形成商品资产，并随着商品销售转为销售成本；“费用”通常在发生期间直接影响当期利润。具体科目、税额和可资本化范围由财务确认。

### 6.7 批次成本状态与版本

采购入库时通常只能确认采购价款，运输费、加工费、辅料包材费和其他入库费可能在月底或次月才取得账单，因此批次成本需要支持逐步确认，而不能只有一个可直接覆盖的最终单价。

| 成本状态 | 含义 | 订单利润口径 |
|---|---|---|
| 暂估 | 采购成本已知，部分后续费用尚未确认或使用合理估计 | 暂估利润 |
| 部分确认 | 部分费用已分摊，仍存在待确认项目 | 调整后利润 |
| 最终确认 | 相关成本账单已基本齐全并完成分摊 | 最终利润 |
| 已关账 | 所属财务期间已关闭 | 不允许覆盖历史成本，只能按财务规则新增调整记录 |

每次成本变化必须形成新版本，至少记录：原成本、新成本、调整金额、费用来源、分摊规则、归属月份、财务入账月份、操作人和时间。不得直接覆盖旧成本而不留痕。

### 6.8 财务月结与费用暂估

“结账”在本文中是指财务月末关账，不是订单结算或供应商付款。财务完成当月凭证入账、成本费用计提、对账、损益结转和报表生成后，关闭该会计期间。

根据权责发生制，费用已经发生但账单尚未取得时，财务应根据合同、报价、对账单、历史费率等可靠依据决定是否暂估，而不是一律等发票或账单到达后再处理。

| 财务期间状态 | 原则处理 |
|---|---|
| 上月未结账 | 实际费用已知则计入上月；金额尚未最终确定但费用已发生，可先暂估后补差 |
| 已结账但报表尚未正式报出 | 经财务审批后，可按公司制度反结账、补录调整凭证并重新结账 |
| 报表已正式报出 | 原则上不直接修改原凭证；在允许期间做调整，或由财务判断是否属于需要追溯处理的前期差错 |

系统应同时保存：

- **费用归属月份**：费用实际服务于哪个业务期间；
- **财务入账月份**：财务凭证实际记入哪个会计期间。

### 6.9 成本补差及财务处理

“成本补差”是内部业务名称，本质是对已经记录的批次成本进行差额调整：

```text
成本补差 = 最终应归属成本 - 已入账或已暂估成本
```

补差不能全部进入当前费用，应根据原批次货物的实际去向处理：

| 原批次货物去向 | 成本补差去向 |
|---|---|
| 尚未销售 | 增加或冲减库存商品金额 |
| 已销售 | 增加或冲减对应销售成本，并关联原订单 |
| 已加工成成品且未销售 | 沿加工批次传递到成品库存成本 |
| 已加工成成品且已销售 | 沿加工和出库关系传递到成品销售成本及订单 |
| 无法合理归属于存货 | 根据费用性质计入当期损益 |

示例：某批次100件，运输费最终为1000元，其中80件已销售、20件仍在库。

```text
每件分摊运输费 = 1000 ÷ 100 = 10元
已销售部分：80 × 10 = 800元，增加销售成本
未销售部分：20 × 10 = 200元，增加库存金额

示意分录：
借：主营业务成本   800
借：库存商品       200
贷：应付账款      1000
```

若此前已经暂估运输费800元，实际账单为1000元，则只补差200元：已销售部分补160元，剩余库存补40元。财务可以选择“直接补差”，也可以“冲回原暂估后按实际金额重新入账”，最终结果应一致。具体会计科目由财务确定。

### 6.10 批次成本与订单利润

订单按 FIFO 找到具体批次后，应保存“订单明细—批次—数量—成本版本”的关系。后续费用到账时，不推翻原 FIFO 匹配关系，而是把该批次的成本差额追溯分配到剩余库存和已销售订单。

订单利润属于经营管理口径，应区分：

| 利润状态 | 含义 |
|---|---|
| 暂估利润 | 使用暂估批次成本计算 |
| 调整后利润 | 后续费用到账并完成部分成本补差后重新计算 |
| 最终利润 | 批次成本最终确认后计算 |

财务总账回答“成本在哪个月正式入账”，订单利润回答“成本最终属于哪个订单”。历史订单利润可以随成本补差重新计算，但必须保留调整前利润、调整金额、调整后利润和成本版本，不能静默覆盖。

### 6.11 财务与审计控制要求

1. 新增费用分摊单，记录费用类型、账单、金额、归属月份、分摊对象、分摊方法和审批记录；
2. 新增成本调整流水，与库存数量流水分开，数量不变时也能单独调整库存金额；
3. 已记账数据不得直接删除或修改关键字段，应通过补充、冲回或调整记录处理；
4. 已关账期间是否允许反结账由财务权限和公司制度控制，系统必须保留完整操作日志；
5. 成本补差必须能够追溯到费用单据、采购/入库批次、加工批次、出库记录和销售订单；
6. 分摊方法、成本状态变化、人工调整和关账操作需要权限隔离及审批；
7. 费用重复导入、重复分摊和超额分摊必须拦截；
8. 库存金额、批次成本、销售成本和费用分摊结果之间应支持对账。

## 七、库存占用与释放

### 7.1 会占用库存的业务单据

- 发货单；
- 库内加工单；
- 调拨单；
- 销售订单；
- 备货任务（是否真实锁库需确认）。

### 7.2 每笔占用必须记录

- 谁占用的；
- 来源单据及明细；
- 占用了哪个 SKU；
- 占用哪个仓库、团队/货主和库存池；
- 原始占用数量；
- 已执行数量；
- 已释放数量；
- 剩余占用数量。

### 7.3 占用结算规则

```text
原始占用 = 已执行 + 已释放 + 剩余占用
```

业务单据完成、取消或作废后，剩余占用必须为 0。

示例：计划发货 100，实际发货 99。

```text
实际扣减 99
释放剩余占用 1
最终该单据占用归零
```

改单时也需要同步处理占用：数量减少则释放差额，数量增加则重新校验可用库存后追加占用。

## 八、库存账本与追溯（三本账）

| 账本 | 作用 | 回答的问题 |
|---|---|---|
| 库存余额 | 记录当前各库存状态的汇总结果 | 现在有多少？ |
| 库存流水 | 记录每次入库、出库、占用、释放、冻结和调整 | 库存为什么增加或减少？ |
| 占用明细 | 记录每张单据对库存的锁定、执行和释放 | 库存被谁锁住、消耗和释放？ |

批次明细是库存余额的来源组成，用于追溯来源、库龄和成本。

必须满足以下核对关系：

```text
库存余额 = 对应批次剩余量合计
占用库存 = 未结清占用明细合计
期末库存 = 期初库存 + 入库 - 出库 ± 调整
```

库存余额可以变化，已生效流水不能直接修改或删除。错误操作通过冲销或反向流水修正。
