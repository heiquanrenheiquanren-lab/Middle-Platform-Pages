## 一、会议背景

对「库存中心 1.0」做需求评审，明确本次库存改造的大框架（库存状态定义、出入库类型、占用与释放、批次与库龄、库存流水规则），以及对接海外仓（含 FBA/亚马逊）时的字段展示、取值与团队归属规则；同时划清本次做与不做的边界。

## 二、本次范围

**本次包含**

- 库存查询、批次库存、库存流水三个页面的口径统一定义。
- 对应海外仓字段的展示与取值规则。
- 库存状态、出入库类型、占用/释放、批次规则、库龄、库存流水规则。
- 对接海外仓：本次暂定 4 个海外仓 + 1 个 FBA（亚马逊），走领星接口。

**本次不包含**

- 海外仓接口技术文档（不同海外仓字段差异后续单独出文档）。
- 单位成本的构成与移动加权平均价的计算（与数量解耦，作为独立需求）。
- 海外仓/平台仓的批次与库龄（含亚马逊）。
- 向店铺同步可销售库存（防超卖，属另一条业务线）。
- 占用明细、在途明细中的平台仓与海外仓部分。

## 三、讨论内容与结论

### 3.1 统一业务口径与库存状态

- 中台只做**一套正式口径**：海外仓、平台仓以外部仓为准；供应商仓、自营仓（坪山仓）、物流中转仓这三类无接口的仓库由中台自行计算。
- **团队颗粒度**贯穿库存查询、批次库存、库存流水三个页面（批次库存本身就是按批次累积到可用/在库总量）。
- 库存状态定义：
  - **可用** = 在库 − 占用 − 冻结；
  - **在库** = 可用 + 占用 + 冻结（即仓库实际数量）；
  - **在途** = 尚未到仓的部分；
  - **待采购**：本次新增，由中台自行计算，仅供应商仓/自营仓/物流中转仓有；用于备货计划参考（计划下多少单、多少尚未采购）。
  - **冻结**：本期只在页面上保留字段，**不做逻辑**（后续盘点单等场景使用）。
- **未知数量不得用 0 代替**：无接口返回该字段时展示 `—`；「0」与「没有」是两回事。
- 出入库类型：每条库存变动都由一个出入库类型产生，不允许直接改数量；后续要用于与财务做进销存报表（期初/本期出库/本期入库/期末等）。枚举值后续补充进 PRD。
- 库存变动引擎（以最终技术方案为准）：由统一的全局方法承担——定时接收外部同步、增加/扣减/占用/释放/冻结/解冻/库存调整、先进先出、团队校验，而不是各业务模块各做一套。

### 3.2 占用、在途与库存流水

- **库存流水只记录可用库存的变动**；占用、在途的变化**不产生流水**。
- 点击「占用」「在途」应能追溯到对应单据（国内自营仓、物流中转仓；后续加工单等也走同一追溯）。
- 占用明细、在途明细**本期只做国内自营仓 + 物流中转仓**；供应商仓无占用/在途概念；平台仓与海外仓（含亚马逊）本期都不做。
- 出库是**一次性动作**，不存在部分发货：如计划发 100 实际发 99，剩余 1 个要**释放**（占用归 0），不能继续挂在占用上。
- 库存流水的打开默认时间范围应**只查当天**（数据量很大，避免页面长时间转圈）。
- 后续业务校验库存是否足够时，**只校验剩余库存量，不再校验库存流水表**。

### 3.3 批次规则

- 批次号生成规则：`PS + 入库时间 + 当日四位流水号`（从 0001 起顺延）。
- 一个批次号只对应**一个 SKU**；粒度 = 批次号 + SKU + 团队。同一入库单同一时间入库、含多个 SKU 与多团队组合（如 SKU-A 分 A/B 团队、SKU-B 分 A/C 团队）时，**拆成多条独立批次明细**（例：5 个 SKU×团队组合 → 5 个批次号），便于按团队和 SKU 追溯。
- 批次**仅支持自营仓 + 物流中转仓**；海外仓、平台仓（含亚马逊）不做批次。
- 领星同样是一个批次号只有一条 SKU，本次设计与其对齐。

### 3.4 库龄规则

- 库龄**只做自营仓 + 物流中转仓**，由中台计算。
- 加权库龄 = 各库龄段数量 × 库龄段 ÷ 总库存量。
- 海外仓库龄、平台仓库龄本期不做（中台库龄会与海外仓对不上，没把握的先不做，优先解决核心问题）。

### 3.5 海外仓对接与团队归属（核心难点）

- 海外仓（除亚马逊）**没有团队概念**，但所有库存变动都**必须归属团队**。
- 拉回一条海外仓库存流水时，通常带**来源单号（业务单号）**和**操作单号**；需要通过这些单号匹配中台单据（发货单号反查、订单号、退货单号等）来确定团队。
- 一条外部库存变动**只能归属一个团队**。
- 同一海外仓返回的流水只有一个「SKU + 仓库 + 总量」，但该总量可能由多个团队构成，需要**按团队拆成多条**（例：100 → 34/33/33），并**保留原始来源单号与操作单号**，保证单据号与总量对得上（最多出现「为什么给我分 34、给他分 33」的团队分配不均问题）。
- **匹配不到团队时的处理（待定）**：会上倾向先允许「团队为空」拉进来；若挂「公共团队」，公共库存不够扣时会出现负库存（明确不允许负库存）；是否允许扣其他团队、是否需要人工指定/人工干预页面，均**尚未定论**，见第五节。
- 亚马逊（FBA）：
  - 天然只有一个团队（亚马逊），**不需要初始化分配**，直接按库存接口覆盖更新即可。
  - 用 **FN SKU** 作为唯一标识请求与识别（同一 FBA 仓内 FN SKU 唯一）；一个中台 SKU 可能对应多个 FN SKU（同店铺多条 listing 用亚马逊配送），颗粒度落到 FN SKU。
  - FBA **不做批次、不做库存流水**，页面上也不展示 FBA 流水。
  - 接口以**领星为准**（领星 V2 版优于 V1，V1 将弃用）；不对接易仓。
  - FBA 口径映射：亚马逊「可售」对应可用；「预留」≈占用；「实际在途」= 发货单数量 − 签收数量，其「可用总数」把在途和占用都加进去，口径偏差大，**不能直接使用**。
  - 需**提前在中台维护 FBA 仓库**（亚马逊明细库存仓库较多，未维护则拉回数据无处展示）。

### 3.6 首次初始化差异的分配规则

- 首次对接海外仓时，中台库存总量与海外仓实际总量会对不上（多团队之和 ≠ 海外仓总量），需要一次性分配：
  - 按该 SKU 在同一海外仓下**中台各团队的现有库存比例**分配海外仓实际总量；
  - **余数**分给比例最大、且剩余数量足够的团队（与「采购单批量收货」导入分配同一套逻辑）；
  - **数量守恒**：分配数量必须等于实际总量，不得出现小数，必须分完。
- **只在首次上线分配一次**；之后按海外仓流水与库存实时覆盖更新，不再分配。
- 分配后若供应链认为不合理，由其**自行通过团队调拨调整**。

### 3.7 未对接海外仓的过渡方案（双分支）

- 已对接：直接使用海外仓库存与流水，**不做订单扣减**。
- 未对接：保留中台原有的**库存计算 + 先进先出扣减**，只需把计算结果放到页面；**不生成库存流水**。
- 存量数据若认为可补，可把扣减的单据类型、数量、团队补进流水；一旦对接完成，从该时间点起由外部流水替代，之前中台自算的流水需迁移/弃用（否则总量与流水对不上）。
- 初始化时技术侧只拉**当前库存**并生成一条「初始化」流水，后续再按流水流转，不拉取全部历史流水。

### 3.8 成本单价口径（与本次解耦）

- 财务侧已排除**月末加权法**与**先进先出法**，最终采用**移动加权平均法**。
- 口径：以**仓库 + SKU** 维度（与团队无关）维护在库量与单价；每次**入库**时重算移动加权平均价，出库按**出库时间对应的最新移动加权平均价**计价。
- 会上倾向：提供单价追溯页面，记录「变动前/变动后、因何单据/入库类型变动」，便于追溯（马总强调）。
- 本次口径不把提货运费、其他出库费、加工费计入移动加权平均价（详见 3.9 与第五节）。

### 3.9 收货批次/提货批次与入库单改造

- **取消收货批次、提货批次**；采购入库侧改为「采购入库批次」，并体现在批次库存。
- 计划新增**入库单**（采购入库时自动生成），用于财务合规的**三单关联**（入库单 + 增值税发票 + 采购单），支撑后续对账；以入库单取代原收货批次。
- 原挂在批次上的费用（提货运费、其他出库费、加工费等）在批次取消后需要有承载方式（会上倾向单独做分摊详情/历史查询/导出页面，待与供应链确认，见第五节）。
- 提货批次去掉后，相关页面与采购单/发货单的批次概念需要同步改造，**改动量较大**，需拆分工。
- 数据清洗：把现有收货批次/提货批次数据洗入库存流水；**生命周期表及相关先进先出逻辑全部下线**。

### 3.10 前端/交互

- 库存流水打开即默认查询当前行仓库 + SKU 的流水，默认只查当天。
- 缺失值统一展示 `—`，不用 0 代替。
- 库存查询需要**排序功能**（杰森反馈缺排序）：**全量排序**、同一时间只允许一个排序条件生效（单页排序无意义，需接口支持）。
- 占用/在途明细弹窗中，除当前占用量外，同一条库存明细分行的可用、在途等数字也一并展示（便于对照）。

## 五、需要产品经理会后与供应链（及财务）确认的事项 ⚠️

> 以下为会上明确提出「需会后与马总/供应链/财务拍板」的事项，确认后需回写 PRD。

- [ ] **1. 海外仓流水匹配不到团队时的归属规则（最高优先级）**
  - 场景：海外仓返回的流水只有 SKU + 仓库 + 数量，且来源单号/操作单号无法匹配到中台单据（如对方直接在领星做的调拨单），无法确定团队。
  - 待拍板：团队是否允许为空？为空后该部分库存如何扣减（明确不允许负库存）；是否挂「公共团队」；公共团队不够扣时是否允许扣其他团队；是否需要「人工指定/人工干预」页面。易仓现做法是「扣公共」，但公共不足时的处理未知，需一并了解。
  - 会上倾向：先允许为空拉入，后续按规则或人工干预处理。**此项不定，开发无处落地**。
- [ ] **2. 公共库存（公共团队）是否参与首次初始化分配**
  - 会上未涉及，产品判断应参与，需与供应链确认。
- [ ] **3. 初始化差异分配规则的最终确认**
  - 确认按中台现有团队库存比例分配；同时说明**现有团队比例本身可能不准**，分配后不合理由供应链自行团队调拨调整。
- [ ] **4. 发货单分批上架（部分上架）时，海外仓上架数量如何分团队**
  - 按发货单实际发货数量比例分配同 SKU 的不同团队，余数给比例大且剩余足够的团队。
  - 需确认：上架数据来源是否要对接「入库上架通知」接口（而非仅靠库存流水），以及不同海外仓的转化层级（1~3 层）。
- [ ] **5. 提货运费、其他出库费、加工费是否计入库存单价（移动加权平均价）**
  - 会上倾向不计入，由财务按当期损益费用化冲销、不分摊到 SKU/团队；产品明确需与财务（杨琴）再确认一次。
- [ ] **6. 批次取消后原有批次费用的承载方式**
  - 提货运费、其他出库费、加工费等原挂在批次上，批次取消后需确认供应链是否仍需该功能；如需，产品另行提供分摊详情/历史查询/导出。
- [ ] **7.「仓库分单」功能是否保留**
  - 若确认费用化冲销、不分摊到 SKU，则该功能无保留必要，直接隐藏。
- [ ] **8. FBA 仓库补齐**
  - 需推动业务/供应链提前把亚马逊明细库存仓库维护进中台，否则拉回库存无处展示。
- [ ] **9. 与对账的衔接口径**
  - 库存流水要为采购对账、物流对账打基础（按单据/团队记录入出库数量）；对账口径后续单独与供应链/财务对齐。

## 七、风险与遗留问题

1. **流水团队归属规则未定**——本次最大阻塞项，直接影响海外仓开发的落地方式。
2. **现有团队库存比例可能不准**——初始化分配结果可能需供应链事后调拨修正。
3. **领星接口限制**——与领星仅签 ERP 使用合同、无二次开发合同，只能基于其现有接口；**接口调用频率受限、易被限流**。
4. **弃用先进先出/批次费用分摊影响面大**——连带影响采购单、发货单、批次费用分摊与生命周期表，改动量较大，需拆分工并做好数据清洗。
5. **FBA 库存无流水、不可追溯单据**——FBA 仅有「在库数」一个数字，占用/在途无法点击打开追溯，也不参与后续订单成本统计（两者无关联）。
6. **海外仓与易仓双库存源**——中台与易仓都对接海外仓、取同一份数据；易仓仍负责尾程发货与预报，中台取执行结果，需关注两边数据一致性。
7. **过渡期数据一致性**——未对接海外仓期间中台自算流水在对接后需迁移/弃用，否则总量与流水对不上（应避免库存查询与流水强耦合）。
