# 供应商列表 PRD

## 1. 需求背景与目标

供应商基础资料、联系人与结算信息需要在同一入口维护，采购人员需要快速定位可合作的供应商，并查看其结算、开票和变更记录。

**目标：提供可查询、可新增、可编辑、可追溯的供应商资料管理页面。**

## 2. 需求效益

- **采购效率**：按编码、名称、采购员及结算条件快速定位供应商。
- **协作清晰**：通过跟进采购员、合作状态、创建信息和操作日志明确资料责任与当前状态。
- **财务协同**：统一维护结算方式、支付方式和开票类型，减少采购与财务间的重复确认。
- **可追溯性**：保存操作日志，便于查询资料变更记录。

## 3. 适用范围与角色

| 角色 | 使用方式 |
| --- | --- |
| 采购员 | 查询、新增和编辑供应商资料；维护跟进采购员、联系及结算信息。 |
| 供应链管理员 | 查看全部供应商资料和操作日志。 |

**本次包含供应商查询、列表、新增、编辑和日志；不包含审批、导入导出和批量删除。**

### 3.1 操作权限

| 权限项 | 控制对象 | 规则 |
| --- | --- | --- |
| **新增供应商** | 列表页“新增供应商”按钮及新增接口 | **权限清单中配置该权限；有权限时展示按钮并允许提交，无权限时隐藏按钮，接口仍需校验权限。** |
| **编辑供应商** | 列表操作列“编辑”按钮及编辑接口 | **权限清单中配置该权限；有权限时展示按钮并允许保存，无权限时隐藏按钮，接口仍需校验权限。** |

本次不增加按组织、采购员或业务线的数据范围限制；供应商查询、查看及日志权限沿用供应链模块现有权限。

## 4. 功能需求

| 功能 | 说明 |
| --- | --- |
| 查询 | 支持供应商编码多值精确匹配、供应商名称或简称模糊查询，以及跟进采购员、结算方式、支付方式单选筛选和供应商等级多选筛选。 |
| 列表 | 字段依次为：供应商名称、供应商编码、简称、供应商等级、合作状态、跟进采购员、结算方式、支付方式、开票类型、创建人、创建时间、操作。 |
| 复制 | 供应商名称、供应商编码右侧提供复制图标，复制成功后提示“已复制”。 |
| 新增/编辑 | 使用同一弹窗维护公司基本信息、联系方式、发货地址、退货地址、财务结算、证明资料与备注；右侧导航可跳转到对应区块。 |
| 日志 | 展示操作类型、日志内容、操作人和操作时间，支持分页。 |

列表不显示勾选框，不提供批量删除按钮。查询组件按 DOM 顺序横向紧凑排列，组件间距为 8px。

## 5. 核心功能逻辑

### 5.1 公司与状态

- 供应商编码由系统按现有最大序号自动生成，新增时只读。
- **供应商名称、供应商简称、信用代码、注册地址、跟进采购员、合作状态、供应商等级为必填**；注册资金、注册日期、可无理由退货、可退货周期、是否包邮为选填。
- 供应商类目为文本输入；供应商等级枚举为 `S级`、`A级`、`B级`、`C级`、`D级`。
- 合作状态枚举：`合作中`、`禁用`；新增默认 `合作中`，在列表中展示，但不作为查询项。
- **合作状态为“禁用”的供应商不得在采购单等下游业务的新建、编辑场景中被选择**；已存在的历史单据继续显示原供应商信息，不删除原关联关系。下游接口提交禁用供应商时应返回校验失败提示。
- 供应商名称不可重复。

### 5.2 联系人与地址

- 联系人、手机号码、联系电话、微信号、电子邮箱均为选填；不维护 QQ 号码。
- 联系人、发货地址、退货地址均支持多条记录，并各自允许设置一条默认记录。
- 重复行使用垃圾桶图标删除。

### 5.3 财务结算与开票

| 字段 | 规则 |
| --- | --- |
| 结算币种 | 必填，枚举：人民币（CNY）、美元（USD）、欧元（EUR）、港币（HKD）、英镑（GBP）、日元（JPY）、澳元（AUD）、加元（CAD）。 |
| 结算方式 | 必填，支持月结 30/90/150/180 天、款到发货及两种预款结算方式。 |
| 支付方式 | 必填，枚举：线上支付宝、线下银行卡、跨境宝。 |
| 开票类型 | 必填，枚举：否、增值税普通发票、增值税专用发票。 |
| **开票税点** | 选择增值税普通发票时显示，**默认不选**，下拉枚举为：免税、1%、3%、6%、9%、13%；选择增值税专用发票时显示，**默认不选**，下拉枚举为：1%、3%、6%、9%、13%。 |
| **实收税点** | 仅选择增值税专用发票时显示，**默认不选**，下拉枚举为：1%、3%、6%、9%、13%。 |

相关证明资料支持 PDF、JPG、PNG 格式，单个文件不超过 10MB；区块标题后统一展示对应提示文案。

### 5.4 操作留痕

- 新增和保存编辑后，系统更新更新人、更新时间，并新增一条操作日志。
- 创建人、创建时间在新增后固定保存；更新人、更新时间保留在数据和操作日志中，不在供应商列表展示。

### 5.5 历史数据迁移与兼容

- **原中台数据库中的历史供应商全部迁移至供应商列表，迁移过程中不得因新页面必填字段缺失而丢弃记录。**
- **历史数据缺少供应商简称、供应商等级、跟进采购员等当前必填字段时，数据库允许这些迁移记录暂时为空，页面对应字段显示为空。**
- 历史数据迁移时不为缺失字段自动填入虚构值；已有字段按原数据展示。
- 新增供应商继续执行当前页面的必填校验；编辑历史供应商时，缺失的必填字段保持空白并由用户补齐，补齐后方可保存。
- 历史数据应保留原供应商唯一标识或建立新旧编码映射，避免重复迁移和重复生成供应商记录。

## 6. 数据、权限与验收

### 数据与权限说明

- 当前页面为原型数据实现；实际系统需按登录用户写入创建人、更新人和操作人。
- **“新增供应商”和“编辑供应商”作为两个独立操作权限加入权限清单，前端控制按钮展示，后端接口同步鉴权。**
- 结算、支付、开票类型及税点属于财务相关资料，应保留编辑日志。
- **禁用供应商不得在采购单等下游业务中继续选择；历史单据的原供应商信息保持可查看。**

### 验收标准

1. 查询可按上述六类条件筛选，重置后恢复默认状态。
2. 列表字段、顺序和名称与本 PRD 一致，无勾选框和批量删除按钮。
3. 新增时自动生成供应商编码，必填项未填写时不可保存，重复名称不可保存。
4. 开票类型为“否”时不显示税点；普通发票显示默认不选的开票税点下拉；专用发票同时显示默认不选的开票税点和实收税点下拉，各下拉枚举符合本 PRD。
5. 历史供应商可完整迁移并进入列表；缺失的简称、供应商等级、跟进采购员等字段显示为空，不影响列表加载和查看。
6. 名称和编码复制图标可复制对应文本并给出成功反馈。
7. 保存后创建/更新信息和操作日志符合上述留痕规则。
8. 无新增权限时不展示“新增供应商”按钮且新增接口拒绝提交；无编辑权限时不展示“编辑”按钮且编辑接口拒绝保存。
9. 禁用供应商不出现在采购单等下游业务的可选供应商中，直接提交禁用供应商时系统阻止并提示。
