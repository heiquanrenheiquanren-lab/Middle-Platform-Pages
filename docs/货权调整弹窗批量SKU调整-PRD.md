# 货权调整弹窗支持批量 SKU 调整 PRD

## 一、文档信息

| 项目 | 内容 |
|---|---|
| 需求名称 | 采购单在途数量的批量货权调整 |
| PRD 版本 | v0.1 草稿版 |
| 需求模式 | 待确认；本文按标准需求粒度整理 |
| 需求来源 | 采购单页面货权调整交互改造 |
| 适用系统 / 模块 | 中台 / 采购管理 / 采购单 |
| 目标页面 | `pages/purchase-orders/index.html` |

## 二、需求概述

### 2.1 背景

当前采购单页面通过“货权调整”打开抽屉，用户需要逐次输入调入平台、调入店铺、调入 SellerSKU/ASIN 和调入数量。逐个处理 SKU 时操作重复，无法一次检索、勾选多个 SKU 并进行统一调整，批量场景下效率较低，也容易漏选或重复录入。

### 2.2 已确认目标

1. 将货权调整从右侧抽屉改为居中弹窗。
2. 支持用户批量搜索 SKU，并勾选多个 SKU 进行调整。
3. 货权调整的业务对象仍然是采购单的“在途数量”，不是库存数量或订单总量。
4. 用户需要填写或确认以下信息：调入平台、调入店铺、调入 SellerSKU/ASIN、调入数量。
5. 交互应优先减少重复操作，并在提交前明确展示本次调整明细。

### 2.3 本次不改变

- 不改变采购单列表的查询、分页、导航和其他操作。
- 不改变货权调整的业务含义，不新增库存、付款、结算、发票等流程。
- 不在本需求内设计真实后端接口；原型使用 mock 数据，但交互和校验应按真实后台使用方式设计。

## 三、业务价值

- 采购运营人员可一次处理多个 SKU，减少重复打开弹窗和重复选择平台、店铺的操作。
- 通过“搜索结果勾选 + 批量设置 + 明细复核”降低漏选、错选和数量录入错误。
- 在提交前集中展示调整明细，便于对采购单在途货权变更进行核对和留痕。

## 四、角色与权限

### 4.1 已知角色

| 角色 | 查看权限 | 操作权限 | 数据范围 | 备注 |
|---|---|---|---|---|
| 采购单操作人员 | 可查看有权限的采购单及在途数量 | 可打开货权调整、搜索 SKU、勾选、填写并提交 | 沿用采购单页面现有数据权限 | 具体角色名称和权限编码待确认 |

### 4.2 权限建议（待确认）

- 弹窗中的平台、店铺、SKU 选项应只展示当前用户有权限的数据。
- 没有货权调整权限时，列表中的“货权调整”按钮隐藏或置灰，并说明原因。
- 提交操作需再次校验采购单状态和用户权限，不能只依赖前端校验。

## 五、业务流程

| 步骤 | 操作角色 | 操作 / 系统处理 | 输出结果 |
|---|---|---|---|
| 1 | 操作人员 | 在采购单列表点击“货权调整” | 打开居中弹窗，带入当前采购单上下文 |
| 2 | 操作人员 | 在批量搜索框输入一个或多个 SKU / SellerSKU / ASIN | 系统按分隔符拆分关键词并展示匹配结果 |
| 3 | 操作人员 | 在结果表勾选需要调整的 SKU，可全选或取消全选 | 选中项进入“本次调整明细” |
| 4 | 操作人员 | 选择调入平台、调入店铺 | 可批量应用到当前选中明细；逐行仍可修改 |
| 5 | 操作人员 | 在明细表填写调入 SellerSKU/ASIN 和调入数量 | 系统实时校验必填、数量和可调整数量 |
| 6 | 操作人员 | 点击“提交调整” | 弹出二次确认，展示 SKU 数和数量合计 |
| 7 | 操作人员 | 确认提交 | 调用货权调整接口；成功提示并关闭弹窗，刷新采购单数据 |
| 8 | 操作人员 | 取消提交或关闭弹窗 | 返回采购单页面；未提交数据不生效 |

## 六、页面与交互说明

### 6.1 弹窗形态

- 使用居中弹窗（Element Plus `el-dialog`），不再使用右侧抽屉。
- 建议宽度：`min(1120px, calc(100vw - 48px))`；最大高度不超过视口高度的 88%。
- 弹窗标题：`货权调整`；副标题显示采购单号和当前在途数量（具体字段口径待确认）。
- 底部固定操作区：左侧显示“已选 N 个 SKU / 调整数量合计 X”，右侧为“取消”“提交调整”。
- 关闭弹窗时，如果存在未提交内容，应二次确认“当前填写内容不会保存，确认关闭吗？”。

### 6.2 推荐布局

1. **采购单上下文区**：采购单号、采购单状态、在途数量等只读信息。
2. **批量搜索区**：输入框、搜索按钮、清空按钮、分隔符说明和已选数量。
3. **搜索结果区**：展示匹配 SKU，可多选、全选、取消全选。
4. **批量设置区**：对选中 SKU 批量选择调入平台和调入店铺，并提供“应用到已选”操作。
5. **调整明细区**：展示每个已选 SKU 的目标 SellerSKU/ASIN、调入数量和删除操作。
6. **提示区**：展示未匹配、重复、在途数量不足、接口异常等反馈。

### 6.3 批量搜索

| 项目 | 规则 |
|---|---|
| 输入内容 | 支持 SKU、SellerSKU、ASIN 混合输入 |
| 分隔符 | 支持换行、逗号、中文逗号、空格、分号；连续分隔符视为一个 |
| 去重 | 搜索前去除重复关键词，保留首次输入顺序 |
| 触发方式 | 点击“搜索”；是否支持回车触发待确认 |
| 结果 | 匹配结果展示 SKU、SellerSKU、ASIN、平台、店铺、可调整在途数量 |
| 未匹配 | 展示未匹配关键词及数量，不阻塞其他匹配结果继续操作 |
| 空输入 | 不发起搜索，提示“请输入 SKU、SellerSKU 或 ASIN” |
| 搜索失败 | 保留用户已选明细，提示“搜索失败，请重试” |

### 6.4 勾选与选中逻辑

- 搜索结果表首列为复选框，支持单选、当前结果全选、取消全选。
- 已经加入明细的 SKU 再次搜索时保持已选状态，不重复添加。
- 选中相同业务 SKU 的重复结果时，只保留一条明细，并提示已去重。
- 清空搜索关键词只清空输入框和结果，不清空已选明细；另提供“清空已选”操作。
- 搜索结果为空时展示空状态，不显示无意义的空表格。

### 6.5 批量设置平台与店铺

- 批量设置区包含“调入平台”和“调入店铺”两个下拉框。
- 未选择 SKU 时，批量设置控件和“应用到已选”按钮置灰，并提示先勾选 SKU。
- 先选择平台，再加载该平台下可用店铺；切换平台时清空不匹配的店铺值。
- 点击“应用到已选”后，将平台和店铺写入所有已选明细；逐行仍可覆盖修改。
- 平台、店铺的枚举值、级联关系和数据权限以后台接口为准，不能在前端写死为业务最终口径。

### 6.6 调整明细表

建议列：

| 列 | 说明 |
|---|---|
| SKU 信息 | 原 SellerSKU、ASIN、平台、店铺；只读 |
| 可调整在途数量 | 当前采购单上下文下可调整的最大数量；只读 |
| 调入平台 | 必填，可逐行修改 |
| 调入店铺 | 必填，受平台级联约束 |
| 调入 SellerSKU/ASIN | 必填，支持输入或从匹配结果选择 |
| 调入数量 | 必填，正整数；不能超过可调整数量 |
| 操作 | 删除本行；删除前不需要二次确认，但提交前必须复核 |

- 调入 SellerSKU/ASIN 默认带入原 SKU 对应值，但允许用户修改为目标货权 SKU。
- 调入数量不默认填满可调整数量时，必须明确展示可调整数量，避免误解。
- 数量输入禁止 0、负数、小数和非数字字符；超过上限时在字段下方展示明确错误。
- 明细至少有一行且所有行校验通过后，才允许点击“提交调整”。

### 6.7 提交与反馈

1. 点击“提交调整”先执行前端完整校验。
2. 校验通过后弹出二次确认：显示采购单号、SKU 行数、调入数量合计，并提示“提交后将调整采购单在途货权”。
3. 确认后按钮进入 loading，禁止重复提交；取消确认返回编辑状态。
4. 成功：提示“货权调整提交成功”，关闭弹窗并刷新采购单行数据。
5. 失败：保留弹窗和已填写内容，展示接口返回原因，允许用户修改后重试。
6. 关闭、取消、提交成功后，下一次打开弹窗应重新初始化，不残留上一次未提交数据。

## 七、数据与字段规则

| 字段名称 | 所属对象 | 类型 | 必填 | 来源 | 规则说明 |
|---|---|---:|:---:|---|---|
| 采购单号 | 采购单上下文 | String | 是 | 当前列表行 | 只读，用于提交关联 |
| 当前在途数量 | 采购单上下文 | Number | 是 | 当前列表行 / 后端 | 只读；提交前需重新获取或校验 |
| 搜索关键词 | 搜索条件 | String | 否 | 用户输入 | 支持多关键词和多种分隔符 |
| 原 SellerSKU | 搜索结果 / 明细 | String | 是 | SKU 主数据 | 只读，用于识别原货权 |
| 原 ASIN | 搜索结果 / 明细 | String | 否 | SKU 主数据 | 无值时显示 `--` |
| 调入平台 | 调整明细 | Enum | 是 | 用户选择 | 必须是当前用户可用平台 |
| 调入店铺 | 调整明细 | Enum | 是 | 用户选择 | 必须属于调入平台且在权限范围内 |
| 调入 SellerSKU/ASIN | 调整明细 | String | 是 | 默认带入或用户输入 | 必须能匹配有效目标 SKU；具体匹配口径待确认 |
| 调入数量 | 调整明细 | Integer | 是 | 用户输入 | `1 <= 数量 <= 可调整在途数量`；是否允许多行合计超过采购单总在途量待确认 |
| 调整原因 | 调整记录 | String | 待确认 | 用户输入或系统 | 当前需求未明确是否需要，不能擅自作为必填 |

### 7.1 数量口径重点

- “可调整在途数量”是按采购单、原货权 SKU、平台/店铺还是采购单总量计算，必须由业务和后端确认。
- 若一次选择多行，需明确校验“每行上限”和“所有行数量合计上限”的关系。
- 提交前必须以后端最新数据为准，防止多人同时操作造成超调。

## 八、状态与业务规则

本弹窗本身不新增持久化状态，主要包含以下前端交互状态：

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| 未打开 | 弹窗关闭 | 点击货权调整打开 |
| 编辑中 | 已打开，可搜索和编辑明细 | 搜索、勾选、批量设置、逐行修改、取消 |
| 校验失败 | 存在必填或数量错误 | 修正错误后继续提交 |
| 提交中 | 已确认提交，接口处理中 | 禁止重复提交；可等待结果 |
| 提交成功 | 后端已接受调整 | 关闭弹窗、刷新采购单 |
| 提交失败 | 后端拒绝或网络错误 | 保留数据，修改或重试 |

业务规则：

1. 只有采购单处于允许调整的状态时，才可打开或提交；允许状态枚举待确认。
2. 目标 SKU、平台、店铺必须通过后端有效性和权限校验。
3. 同一采购单、同一原货权、同一目标货权的重复明细需要合并还是禁止重复，待确认；原型默认去重并提示。
4. 提交接口应支持幂等键，避免网络重试产生重复调整。

## 九、异常与边界场景

| 场景 | 触发条件 | 系统处理 | 用户提示 |
|---|---|---|---|
| 未输入关键词 | 点击搜索但输入为空 | 不请求接口 | 请输入 SKU、SellerSKU 或 ASIN |
| 部分未匹配 | 多关键词中部分无结果 | 展示已匹配结果，单独列出未匹配项 | 共 X 个关键词，Y 个未匹配 |
| 搜索结果为空 | 全部关键词无匹配 | 展示空状态，保留输入 | 未找到匹配 SKU，请检查关键词 |
| 未勾选提交 | 明细为空 | 阻止提交 | 请至少选择 1 个 SKU |
| 必填缺失 | 平台、店铺、目标 SKU 或数量为空 | 定位到首个错误字段 | 请完善必填信息 |
| 数量非法 | 0、负数、小数、非数字或超上限 | 阻止提交 | 请输入不超过可调整数量的正整数 |
| 平台店铺不匹配 | 切换平台后店铺失效 | 清空店铺并要求重新选择 | 当前店铺不属于所选平台 |
| 权限不足 | 用户无采购单或目标店铺权限 | 后端拒绝并保留数据 | 无权限执行该货权调整 |
| 在途数量已变化 | 他人已先调整 | 后端以最新数据校验并拒绝旧提交 | 可调整数量已变化，请刷新后重试 |
| 重复提交 | 用户连续点击或网络重试 | loading + 幂等控制 | 正在提交，请勿重复操作 |
| 接口失败 | 网络或服务异常 | 不关闭弹窗，允许重试 | 提交失败，请稍后重试 |
| 关闭未保存 | 编辑中点击关闭 | 二次确认 | 当前填写内容不会保存，确认关闭吗？ |

## 十一、实现建议（给执行本 PRD 的 AI）

- 技术栈固定为 Vue 3 + Element Plus；弹窗使用 `el-dialog`，表格使用 `el-table`，多选使用 `selection`，下拉使用 `el-select`。
- 原型应保留现有采购单页面和入口，只替换货权调整交互。
- 优先采用相对资源路径；若无构建环境，允许使用本地 vendor 依赖或可靠 CDN，但核心交互不能因单个外部资源失效而无法展示。
- 将搜索结果、已选明细、批量设置值、校验错误和提交状态拆分为独立响应式状态，避免搜索时覆盖已填写明细。
- 所有演示数据使用 mock 数据，并提供至少 5 个可搜索 SKU，覆盖匹配、未匹配、平台店铺级联和数量校验场景。

## 十二、验收标准摘要

### 12.1 入口与弹窗

- [ ] 在采购单页面点击“货权调整”后打开居中弹窗，不出现右侧抽屉。
- [ ] 弹窗展示当前采购单上下文，关闭后不影响采购单页面其他筛选和分页状态。
- [ ] 编辑中关闭会出现未保存确认；取消关闭可继续编辑。

### 12.2 批量搜索与选择

- [ ] 输入换行、逗号、中文逗号或空格分隔的多个 SKU / SellerSKU / ASIN，可一次搜索。
- [ ] 结果支持单选、当前结果全选、取消全选和清空已选。
- [ ] 未匹配关键词单独提示；已有明细不会因再次搜索而丢失或重复。

### 12.3 批量调整

- [ ] 选中多个 SKU 后，可一次设置调入平台和调入店铺并应用到已选项。
- [ ] 明细表支持逐行修改目标 SellerSKU/ASIN、调入数量和删除行。
- [ ] 未选 SKU 时批量设置不可用；切换平台后不允许保留失效店铺。

### 12.4 校验与提交

- [ ] 平台、店铺、目标 SKU、数量缺失时不能提交，并定位错误字段。
- [ ] 数量只能为正整数，不能超过可调整在途数量；提交前校验合计上限（规则以待确认口径为准）。
- [ ] 提交前出现二次确认，显示采购单号、SKU 行数和数量合计。
- [ ] 提交中按钮 loading 且不能重复提交；成功关闭并刷新，失败保留填写内容并可重试。

### 12.5 权限与留痕

- [ ] 无权限用户不能执行货权调整，前端展示与后端校验一致。
- [ ] 后端以最新在途数量和采购单状态进行最终校验。
- [ ] 若确认需要审计日志，日志至少包含操作人、时间、采购单号、原货权、目标货权、数量和提交结果。

## 十三、待确认问题
