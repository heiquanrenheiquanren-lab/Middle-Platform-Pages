# 库存流水团队归属对接方案

> 版本：v0.4  
> 日期：2026-10-20  
> 适用范围：库存中心 2.0，外部仓库存流水归属团队  
> 说明：本文为通用对接方案，当前以跨跃猫作为首个样例、万邑通（WINIT）作为第二个样例；后续服务商按同一逻辑补充

---

## 一、目标

外部仓的库存流水本身没有中台团队，需要把每条出库流水归属到正确团队。

当前业务口径：

```text
销售平台 = 团队
```

所以只要能拿到流水对应的销售平台，就能锁定团队。

---

## 二、核心逻辑

```text
库存流水
  ↓
筛选出库流水（关联单据类型 = 出库单）
  ↓
用关联单号查出库单
  ↓
取销售平台（salesPlatform）
  ↓
销售平台映射为团队
  ↓
回写库存流水 / 库存余额的团队
```

查不到出库单、销售平台为空、平台没有对应团队时，进入异常池，不挂“公共团队”。

部分服务商不返回销售平台（如万邑通），改用平台订单号判定平台，见第四章。

---

## 三、要对接的接口（以跨跃猫为例）

| 顺序 | 接口 | 作用 | 是否必须 |
|---:|---|---|---|
| 1 | 库存流水 `pageStockFlow` | 拉库存流水，取出库单号 | 必须 |
| 2 | 小包出库单列表 `outboundOrder/pageList` | 用出库单号换销售平台、平台单号 | **主方案** |
| 3 | 大货出库单列表 `outboundOrder/big/pageList` | 小包查不到时兜底 | 建议 |
| 4 | 小包出库单详情 `outboundOrder/detail` | 单票排查、来源追溯 | 可选 |
| 5 | 退件单详情 `returnOrder/detail` | 退件流水先查出库单号 | 后续扩展 |

> 其他服务商的接口名称可能不同，但作用一致：库存流水、出库单/来源单据、详情兜底。

### 结论

- **主对接：库存流水 + 小包出库单列表。**
- 如果出库单可能是大货，再补一个大货出库单列表。
- **详情接口不作为主方案**：返回内容多、字段重，只用于查不到或需要追溯来源时。
- 退件、入库、盘点、移库、调整等流水不走这条链路，单独处理。

## 四、万邑通（WINIT）样例

### 4.1 接口总览

统一入口 `https://openapi.winit.com.cn/openapi/service`（沙箱 `https://sandboxopenapi.winit.com.cn/openapi/service`），`action` 传接口名称，`data` 传业务参数，签名方式 Token + md5。

| 顺序 | 接口 | `action` | 作用 | 是否必须 |
|---:|---|---|---|---|
| 1 | 查询总库存 | `queryWarehouseStorage` | 拉仓库 + SKU 库存，做初始化分配基数和库存对账 | 必须 |
| 2 | 查询库存流水 | `winit.inventory.pageInvInouts` | 拉库存变动流水，`docType=OUTBOUND` 时 `docNo` 即出库单号 | 必须 |
| 3 | 查询出库单列表 | `queryOutboundOrderList` | 用出库单号换平台订单号 `platformOrderId` | **主方案** |
| 4 | 查询入库单列表 | `winit.wh.inbound.getOrderList` | 入库单状态、入库在途追溯 | 建议 |
| 5 | 查询出库单详情 | `queryOutboundOrder` | 单票兜底，含 `platformOrderId`，示例里另有 `storeType` | 可选 |

### 4.2 查询总库存 `queryWarehouseStorage`

| 参数 | 必填 | 说明 |
|---|---|---|
| `warehouseCode` | 是 | 仓库 Code（历史 `warehouseID` 仍兼容） |
| `isActive` | 否 | 商品是否有效 Y/N |
| `inReturnInventory` | 否 | 是否返回退货库存 Y/N |
| `isFilterZeroInventory` | 否 | 是否过滤在库库存为 0 的数据 |
| `pageSize` / `pageNum` | 否 | 分页 |

返回关键字段：

| 字段 | 说明 |
|---|---|
| `productCode` / `merchandiseSerno` / `specification` | SKU / 商品条码 / 规格 |
| `inStockQty` | 在库总库存 = 可用 + 待发 + 丢失确认中 + 增值处理中 + 在库异常 + 待销毁 + 失效VAT冻结 + 禁止出库 |
| `qtyAvailable` | 可用库存，对账和比例分摊基数取这个 |
| `qtyWaitOut` | 待发数量（订单及调拨/调整出库占用，不含销毁） |
| `pipelineInventory` | 在途待入库数量 |
| `qtyFrozen` / `qtyDestruction` / `qtyLostConfirming` / `addValueFrozenQty` / `prohibitFrozenQty` / `prohibitUsableQty` | 各类冻结、异常库存 |
| `preSaleWaitOutQty` | 预售待发数量（需开通预售权限） |

注意：

- 接口版本建议固定 `3.0`：3.0 把退货库存合并到关联 SKU 返回，1.0 是单独一行。
- 已停用字段不要再取：`inventory`、`reservedInventory`、`qtySw`、`qtySellHisOut`、`qtyShareStorage`，以及长宽高重量。
- 限流默认 200 次/分钟，比其它接口低，全量拉取要控频。
- 中台口径：可售取 `qtyAvailable`，在途取 `pipelineInventory`，不能把 `inStockQty` 直接当可售。

### 4.3 查询库存流水 `winit.inventory.pageInvInouts`

| 参数 | 必填 | 说明 |
|---|---|---|
| `skuCode` | 条件必填 | 商品编码；按 `docNo` 查询时可不传 |
| `warehouseCode` | 条件必填 | 仓库编码；按 `docNo` 查询时可不传 |
| `startDate` / `endDate` | 条件必填 | 日期区间最大 31 天 |
| `docNo` | 否 | 单据号，支持入库单号、出库单号、退货单号、调整单号等 |
| `docType` | 否 | `INBOUND` 入库、`OUTBOUND` 出库、`ADJUSTMENT` 调整、`ALLOCATION_OUT` 调拨出库、`ALLOCATION_IN` 调拨入库、`INBOUND_RETURN` 退货入库、`INBOUND_OVERSEAS` 直发入库 |
| `specification` | 否 | 商品规格 |
| `pageVo.pageNo` / `pageVo.pageSize` | 是 | 分页 |

返回关键字段：`skuCode`、`merchandiseSerno`、`specification`、`warehouseCode`、`docType`、`docNo`、`startQty` 期初、`endQty` 期末、`changeQty` 变动、`changeDate`、`remark`、`merchandiseGrade`、`uuid`（建议做幂等键）。

注意：

- 入库、出库、调整、调拨都在同一个流水接口里，靠 `docType` 区分；只有 `OUTBOUND` 能走团队归属。
- 示例返回里还有 `salesChannel`、`provideChannel`，参数表未定义，疑似销售渠道，待确认。

### 4.4 查询入库单列表 `winit.wh.inbound.getOrderList`

权限前提：仅开通“第三方单品条码管理权限”后可调用。

| 参数 | 必填 | 说明 |
|---|---|---|
| `winitProductCode` | 是 | WINIT 产品编码（取自“查询头程服务”） |
| `pageParams.pageNo` / `pageParams.pageSize` | 是 | 分页 |
| `orderType` | 否 | `SD` 标准海外仓入库、`DW` 直发海外验入库、`DI` 直发自验入库 |
| `destinationWareHouseCode` | 否 | 目的仓编码 |
| `inspectionWareHouseCode` | 否 | 验货仓编码 |
| `orderCreateDateStart` / `orderCreateDateEnd` | 否 | 下单日期区间 |

返回：`orderNo` 入库单号、`status` 状态编码、`weight`、`volume`、`totalPackageQty`、`totalItemQty`、验货重量/体积/包裹数/单品数、`orderCreateDate`、`pageParams`。

注意：

- 返回的是入库单头和汇总，**不含 SKU 明细**；明细要再调“查询入库单详情”（id/39）。
- 与库存流水关联：流水的 `docNo` 即这里的 `orderNo`。
- `winitProductCode` 必填，无法只按仓库和时间全量拉。

### 4.5 查询出库单列表 `queryOutboundOrderList`

| 参数 | 必填 | 说明 |
|---|---|---|
| `dateOrderedStartDate` / `dateOrderedEndDate` | 是 | 出库单提交日期，`yyyy-MM-dd` |
| `pageSize` / `pageNum` | 是 | 分页 |
| `outboundOrderNum` | 否 | 海外仓出库单号 |
| `sellerOrderNo` | 否 | 卖家订单号 |
| `status` | 否 | 订单状态编码；不传默认不含 `VO`（已作废） |
| `productSku` / `productValue` / `productName` | 否 | 按商品过滤 |
| `trackingNo` / `receiverName` / `warehouseId` | 否 | 按物流、收件人、仓库过滤 |

返回关键字段：`documentNo` 出库单号、`platformOrderId` 平台订单号、`sellerOrderNo`、`status` / `statusName`、`warehouseId` / `warehouseName`、`deliverywayName`、`trackingNo`、`dateOrdered`、`dateFinish`、`eBaySellerID`、`isEBayOrder`、`packageList`。

注意：列表返回 `platformOrderId`，**不返回 `salesPlatform`**，也没有店铺字段。

### 4.6 平台判定规则

| 平台 | `platformOrderId` 形态 | 示例 |
|---|---|---|
| Amazon | 3-7-7 位数字，以 `-` 分隔 | `902-3159896-139091` |
| TikTok | 19 位纯数字 | `576461413038785752` |
| Shopify | `gid://shopify/Order/` + 数字 | `gid://shopify/Order/5926778994799` |
| eBay | 用 `eBaySellerID`、`isEBayOrder=Y` 直接识别 | — |
| 其他平台 | 单号形态无固定规则 | 需补规则或人工登记 |

判定链路：

```text
库存流水（docType = OUTBOUND）
  ↓ docNo
查询出库单列表 queryOutboundOrderList
  ↓ platformOrderId
按单号规则判定平台
  ↓
平台映射为团队
```

规则未命中时进入异常池，不能默认按某个平台挂团队。

### 4.7 重点规则

1. **`platformOrderId` 的文档口径是“平台订单号 / 订单参考号”**。如果下单方填的是自定义参考号，格式规则会失效，必须进异常池。
2. **`sellerOrderNo` 是卖家自定义订单号**，不能作为平台判定依据。
3. **列表接口没有 `storeType`**；详情接口 `queryOutboundOrder` 的返回示例里出现过 `storeType`（如 `other`），但参数表未列出，需实测确认。若能稳定返回，应优先用 `storeType`，平台单号规则降为兜底。
4. **万邑通没有小包 / 大货两套出库单接口**，出库单统一走 `queryOutboundOrderList`；创建时用 `inventoryServiceType` 区分 `2B`（ToB 整箱出库）和 `2C`（ToC 销售出库）。
5. **库存流水 `pageInvInouts` 的 `docNo` 非必传**：传入后可以只按单据号查询；不传时必须带 `skuCode`、`warehouseCode`，且日期区间最大 31 天。
6. **库存流水返回示例里还有 `salesChannel`、`provideChannel`**，文档参数表未定义，疑似销售渠道，需向服务商确认。
7. **查询总库存必须按仓库拉**，`warehouseCode` 必填；`inStockQty` 不等于可用库存，分配基数只能用 `qtyAvailable`。
8. **入库单列表必须传 `winitProductCode`**，且只返回单头汇总，SKU 明细要再查入库单详情。
9. **四个列表接口的分页参数命名不统一**：`queryWarehouseStorage` 和 `queryOutboundOrderList` 用 `pageSize/pageNum`，`pageInvInouts` 用 `pageVo.pageNo/pageVo.pageSize`，`getOrderList` 用 `pageParams.pageNo/pageParams.pageSize`，不要复用同一套分页 DTO。

### 4.8 待确认问题（万邑通）

1. `queryOutboundOrder` 是否稳定返回 `storeType`？
2. `platformOrderId` 是否总是平台真实订单号，而不是订单参考号？
3. `docType = OUTBOUND` 是否同时覆盖 2B 整箱出库和 2C 销售出库？
4. `salesChannel`、`provideChannel` 的字段含义与取值是什么？
5. 查询总库存的退货库存（`inReturnInventory=Y`、`isReturnInventory=Y`）是否计入中台可分配总量？
6. 查询入库单列表必须传 `winitProductCode`，多产品编码的客户是否需要逐个编码循环拉取？

### 必须拿到

| 信息 | 来源 | 用途 |
|---|---|---|
| `relateOrderType` | 库存流水 | 确认是出库单（值为 `2`） |
| `relateOrderNo` | 库存流水 | 关联出库单 |
| `outboundOrderNo` | 出库单接口 | 校验单据匹配 |
| `salesPlatform` | 出库单接口 | 销售平台，直接对应团队 |

### 建议一并保存

| 信息 | 用途 |
|---|---|
| `platformOrderNo` | 平台单号，用于来源单据追溯 |
| `status` | 判断出库单是否有效 |
| `whCode`、`sku`、`operateTime` | 库存核对、幂等 |

## 六、重点规则（跨跃猫）

1. **`relateOrderNo` 不是平台订单号**，是当前服务商系统内部的关联单据号，需要再去查出库单。
2. **一个出库单只返回一个 `salesPlatform`**，所以一个出库单只能锁一个团队。
3. **`platformOrderNo` 不是锁团队的必需字段**，只用于回答“这笔流水来自哪张平台订单”；可能是多个逗号分隔的平台单号，但团队仍然只有一个。
4. **当前两个出库接口（小包列表、详情）都不返回店铺字段**。`companyName` 是收件人公司，不是店铺。
5. **销售平台为空、出库单查不到、平台映射缺失**时，进入异常池；按 PRD 规则做比例分摊或人工处理，不能挂公共团队。
6. **只有出库流水走这条链路**。退件、入库、盘点、移库、调整等流水没有销售平台，不能直接锁团队。
7. **一张出库单如果合并了多个平台的订单**，单值 `salesPlatform` 表达不了多个平台，需要按平台拆单或拆流水，不能随便取一个平台当整单团队。
8. **批量处理时先按出库单号去重**，同一张出库单可能对应多条 SKU/批次流水。

3. 一张出库单是否可能合并多个平台的订单？
4. 后续团队是否会按店铺细分？如果会，当前两个出库接口不返回店铺，需要补其他接口。

## 八、后续服务商怎么接

其他服务商按同一逻辑补充，不需要改整体方案：

```text
库存流水 → 关联单号 → 出库单/来源单据 → 销售平台 → 团队
```

每接一家服务商，只需要确认四件事：

1. 库存流水接口能不能拿到关联单据号；
2. 能不能用这个单号查到出库单或来源单据；
3. 来源单据是否返回销售平台；
4. 销售平台是否能映射到中台团队。

如果服务商不返回销售平台、只返回店铺，就用“店铺 → 团队”映射；两者都没有，就不能自动锁团队，进入异常池。
