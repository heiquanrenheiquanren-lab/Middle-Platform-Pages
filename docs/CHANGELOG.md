### v1.7.0 — 2026-08-09 · 接入需求预测与新版备货计划

**变更目的**：将外部 Element Plus 需求预测/备货计划原型接入中台，并统一使用现有浅色导航。

### v1.6.2 — 2026-08-09 · 货权调整弹窗全面重做

**变更目的**：将采购单货权调整弹窗从「搜索 + 已选」两步分拆模式重构为单列表直填模式，同时优化搜索能力和数据展示。

#### 一、弹窗结构重构
1. **两步合一**：删除原来的「步骤 2 设置调入信息」独立表格，来源信息和调入输入框合并在同一个列表中
2. **新结构**：勾选 | 来源 SKU | 采购单号 | 品名 | 来源平台/店铺/团队 | 采购数 | 在途数 | 可调整数 | 调入平台 | 调入店铺 | 调入 SellerSKU/ASIN | 调入数量 | 操作
3. **多次搜索追加**：重复搜索不会清空已存在的行，新结果追加到列表末尾，避免用户丢失已填写内容

#### 二、搜索增强
1. **新增采购单号搜索**：下拉选择「采购单号（易仓）/ 采购单号（领星）/ 采购跟踪号」+ 输入框，默认「采购单号（易仓）」
2. **SKU 与采购单号可组合查询**
3. **无在途数量 SKU 直接过滤**：不在结果中展示

#### 三、数据展示优化
1. **删除顶部固定来源汇总区**：因用户可一次操作多个采购单/多团队 SKU
2. **删除「匹配状态」列**
3. **新增「来源团队」字段**：与平台/店铺合并显示为「平台 / 店铺 / 团队」
4. **采购单号格式化**：有领星单号 → 主 `领星 LX-xxx`，小字 `采购跟踪 TRK-xxx`；否则 → 主 `易仓 BDTxxx`，小字 `采购跟踪 TRK-xxx`
5. **数字去单位**：采购数/在途数/可调整数列只显示数字

#### 四、交互优化
1. **删除「校验」列**：提交时统一校验所有剩余行，错误用消息提示
2. **删除「模拟提交失败」复选框**
3. **底部精简**：去掉「校验在提交时统一进行」文案
4. **批量操作仅对勾选行生效**：「应用到勾选 SKU」「按可调整数填充勾选行」
5. **删除顶部「全选可调整项」「清空已选」按钮**：统一用表格左上角勾选框操作

### v1.6.1 — 2026-08-09 · 发货弹窗重做 + 手动完结 + 收货优化

**变更目的**：发货操作从简单状态流转升级为完整弹窗交互；新增手动完结通道，解决「实际已收货但系统未完全匹配」的异常场景；收货弹窗增加收发差异列。

#### 一、发货弹窗（新建）
1. **交互设计**：替换原 `shipDocument` 一键发货为完整弹窗 `openShip`，表格列出所有 SKU 发货明细
2. **列设计**：SKU | 产品信息 | 计划号 | 申报数量 | 提货数量 | 剩余可发 | 本次发货数量（固定右侧）| 申发差异 | 提发差异 | 发货备注 | 差异原因
3. **快捷按钮**：「按剩余可发数量填充」一键填满所有行
4. **差异处理**：当发货数量 ≠ 提货数量时，必须选择差异原因（同提货弹窗的差异原因枚举）
5. **固定列**：SKU + 产品信息左固定，本次发货数量右固定
6. **底部汇总**：已选 SKU 数 + 本次发货总计 + 提交后状态（待收货）

#### 二、手动完结弹窗（新建）
1. **两个入口**：待收货/部分收货状态下的操作列「手动完成」按钮
2. **支持批量**：选中多张单据后可批量手动完结
3. **表单字段**：完结原因（必选：部分到货/全部到货未扫描/货物丢失/物流异常/其他）+ 备注（选填）
4. **单条弹窗**：显示履约状态、申报数量、已发货、已收货、未收数量
5. **批量弹窗**：仅显示选中单据数量
6. **提交后**：状态直接转为「已完成」（终态）

#### 三、收货弹窗优化
1. **新增「收发差异」列**：`(累计收货 + 本次收货) − 累计发货`，正数多收、负数少收，悬浮问号提示
2. **条件显示**：收货数量已勾选的行才计算差异

#### 四、二级列表优化
1. 展开面板 SKU 明细表新增「发货数量」和「申发差异」两列
2. 申发差异 = 申报数量 − 发货数量

#### 五、其他优化
1. 查询区从 5 列改为 4 列布局（紧凑）
2. 列表空状态提示：筛选无结果时显示 `el-empty` "暂无符合条件的发货单"
3. 待收货、部分收货状态统一显示「手动完成」按钮

**版本号**：`VER = 1.6.1`

   - `buildProcessingRows` 中 `targetDocs.sort((a,b)=>a.id.localeCompare(b.id))`，同发货单的组合 SKU 靠在一起

**业务影响**：
- 横向滚动大幅减少，一屏能看完更多信息
- 操作效率提升：搜索 + 一键填满 + 清空，批量加工可以几秒完成

#### 3.1.1 货权调整弹窗（批量版）

**核心功能文件**：`pages/purchase-orders/ownership.js` + `ownership.css`

**来源货权（默认固定）**：Shopify · B端独立站

**目标货权**：调入平台 + 调入店铺 + 调入 SellerSKU/ASIN + 调入数量

**三步交互流程**：

```
Step 1 搜索并选 SKU
  ↓ 输入 SKU/SellerSKU/ASIN（支持多码逗号/空格/换行分隔，上限 100 个）
  ↓ 搜索结果 → 表格勾选（跨页记忆选中）
  ↓ 未匹配编码在顶部黄色 Warning 展示

Step 2 设置调入信息（批量 + 逐行）
  ↓ 顶部批量字段：调入平台 → 调入店铺（平台级联清空店铺）→ 批量应用按钮
  ↓ 批量应用后表格每行可单独覆盖
  ↓ 每行校验：平台必选 + 店铺必选 + SellerSKU/ASIN 必填 + 数量(1~在途数 整数)
  ↓ "校验"列：通过(绿色) / 待补充 + 第一条错误原因(橙色)

Step 3 提交确认
  ↓ 汇总弹窗：调入货权来源 → 目标汇总文本 + X 条明细 + 总调整数量
  ↓ 确认后立即更新在途货权归属
```

**校验规则（`validateRow` 函数）**：
```
errors = []
if (!form.platform)    errors.push('请选择平台')
if (!form.store)       errors.push('请选择店铺')
if (!form.targetSku)   errors.push('请补充 SellerSKU / ASIN')
qty = Number(form.quantity)
if (!整数 || qty<=0 || qty>row.transit)  errors.push('数量需为 1-'+row.transit+' 的整数')
```

**平台 / 店铺级联关系**（`storesFor` 计算属性）：
- Amazon → [Amazon-US 旗舰店, Amazon-DE 家居店, Amazon-US 运动店]
- Shopify → [B端独立站, C端官网, Shopify 测试店]
- eBay → [eBay-US 主店, eBay-DE 汽配店]

**关键交互细节**：
- 批量应用时，只覆盖"当前为空"的字段（还是强制覆盖？待确认；当前原型是强制覆盖）
- 关闭弹窗：有输入或已选中 → 二次确认"已填内容将丢失，确认关闭？"
- 选中数 + 有校验错误条数 → 底部"确认调整 (X)"按钮文字实时显示 `X 条有效 / Y 条待补充`

### 3.2 采购计划 (purchase-plan)

**所在路径**：`pages/purchase-plan/`

**页面角色**：从需求预测、安全库存、备货计划汇总后，形成面向供应商的采购建议清单，计划员确认/调整后生成采购单。

**典型字段**：计划号、SKU、建议采购量、供应商、交货期、状态（待确认 / 已转采购单 / 已取消等）

**侧边栏菜单**：库存管理下无激活项；计划管理下无激活项；供应链协同下显示采购单(可跳转)、发货单(可跳转)。

### 3.3 发货计划 (shipment-plan)

**所在路径**：`pages/shipment-plan/`

**页面角色**：运营根据"需求预测 + 海外仓库存水位"创建发货计划，指定发货仓、目的仓、运输方式；后续计划被"发货单"引用，一张发货计划可被多个 SKU 引用。

**原型状态数据 (shipment-plan 共 62 条)**：`待确认(13) / 待发货(13) / 运输中(12) / 已完成(12) / 已作废(12)`

**页面特色交互**：
- SKU 编码搜索下拉（SKU / 供应商料号 / 领星 SKU / SellerSKU / FNSKU / ASIN 切换）
- 多编码批量输入（逗号、空格、换行分隔）
- "发货计划管理清单"4个Tab（新建发货计划等）
- 行内可编辑：计划备注、预计发货日期、预计到货日期、箱数
- "生成发货单"按钮（批量生成发货单）

### 3.4 备货计划 (stock-plan)

**页面角色**：综合需求预测、在库库存、在途库存、安全库存阈值，计算建议补货量，是采购计划的上游输入。

**菜单定位**：计划管理下「备货计划」（侧边栏激活态）

### 3.5 发货单 (shipment-orders) ✨新增

**所在路径**：`pages/shipment-orders/`

**页面角色**：供应链协同的执行层单据，运营根据"发货计划"生成实际的出库发运单。**一张发货单可包含多个 SKU，每个 SKU 对应一个发货计划**（页面标题下方说明）。

#### 3.5.1 发货单状态流转与标签页

```
草稿 → 待提货 → [提货完成]
                    ├─ 含组合品（skuType='组合'）→ 可加工 → [加工完成] → 待发货 → 待收货 → 已完成
                    └─ 无组合品 → 待发货 → 待收货 → 已完成
（作废节点：草稿 / 待提货）
```

> ⚠ v1.5.3 变更：取消"部分提货"状态。提货后不再停留在中间状态，而是根据是否含组合品直接转入"可加工"或"待发货"。

**特殊标签页**：
- `可加工`：**独立状态**（v1.5.3 起）。提货完成后含组合品的发货单自动转入此状态，需通过物流加工后才能进入"待发货"
- `全部`：不做状态过滤

**状态标签颜色规则 (`tagType`)**：
- success（绿）：已完成 / 已签收
- warning（黄）：待收货 / 部分收货 / 可加工
- info（灰）：草稿 / 未提交 / 待提货 / 未发货 / 已作废
- danger（红）：预留（当前原型未触发）

#### 3.5.2 查询条件

| 条件 | 控件类型 | 说明 |
|---|---|---|
| 发货单号 | el-input 可清空 | 中台单号 DNxxxxxx |
| 计划单号 | el-input 可清空 | 对应上游发货计划 FPxxxxxx |
| SKU | el-input 可清空 | 匹配 items 子表 |
| 发货仓 | el-select 可筛选可清空 | 深圳仓 / 东莞工厂 / 义乌仓 |
| 履约状态 | el-select 可清空 | 除"全部""可加工"之外的纯状态值 |
| 操作 | 查询 / 重置 | 查询把 query 同步到 appliedQuery |

#### 3.5.3 新建发货单（必填校验）

**弹窗尺寸**：`92vw × 92vh`，居中大弹窗

**基础公共字段校验 (`createRules`)**：
- 发货仓 `from`：必填
- 目的仓 `to`：必填（美国西部仓 / 美国东部仓 / 德国仓 / 英国仓）
- 发货方式 `shipMode`：必填（仓库发货 / 工厂直发 / 供应商直发）
- 头程服务商 `provider`：必填（马士基 / DHL / 顺丰国际）
- 运输方式 `transport`：必填（海运 / 空运 / 快递）
- 物流渠道 `channel`：必填（标准海运 / 空派 / 国际快递）

**地址字段**：发货地址 / 收货地址（联系人、电话、国家、省、市、区、详细地址、邮编）；国家自动带出，但允许覆盖。

**SKU 选择约束**：
- `canAddSku`：只有基础 6 字段全填完才能点"＋ 添加 SKU"
- 打开的 SKU 选择弹窗：同样支持多条件查询（SKU/计划号/仓库/目的国/状态）+ 全表勾选
- 每 SKU 必填：申报数量（默认 = 计划发货数量，可手动改，最大不超过"发货计划剩余数量"）
- 重量/体积/尺寸：从 SKU 档案自动带出，可覆盖
- 批量删除、批量修改申报数量、批量应用备注
- **同一目的仓**（v1.5.3）：SKU 选择弹窗和新建区域均有黄色提示，同一发货单仅支持同一目的仓的货物合并发运
- **FBA 混发校验**（v1.5.3 刚性规则）：`confirmSkuSelection` 确认选择时，若选中 SKU 同时包含 Amazon 平台和非 Amazon 平台，硬阻止并提示错误

**两种提交模式**：
- **保存草稿**：生成草稿单号 `DRAFT{yyyyMMdd}{序号}`，状态 = 草稿
- **提交**：`createFormRef.validate()` 通过 + 至少选 1 个 SKU → 生成 `DN{时间戳}` 单号，状态 = 待提货

#### 3.5.4 发货单表格核心字段

**单号分组（展开子行）**：
- 中台发货单、易仓发货单、发货方式
- 发货仓 → 收货仓、物流渠道、运输方式
- SKU 个数、计划数量、申报数量、提货数量
- 预计发货 / 到货日期
- 物流单号、已收货数量、待收货数量
- 实际运费、清关税费、头程费用合计

**行级操作按钮**（按状态出现）：
- 草稿 → 提交/作废
- 待提货 → 提货 / 作废
- 可加工 → 加工（v1.5.3 新增，打开物流加工弹窗）
- 待发货 → 发货
- 待收货 → 收货
- 部分收货 → 收货 / 手动完成
- 已完成 → （仅查看）
- 已作废 → （仅查看）

#### 3.5.5 物流加工（批量）

- 针对"待提货/可加工"的发货单批量执行
- 表单：履约批次类型（提货/发货/收货）、日期、物流单号
- 批量按 SKU 分配本次批次数量

#### 3.5.6 费用与轨迹导入

- 导入物流费用：头程运费 / 清关税费等
- 导入轨迹信息：运输节点、签收节点

#### 3.5.7 履约批次子表

- 每张发货单下对应多条：`{no: 批次号, type: 提货/发货/收货, date, skuCount, status}`

## 四、导航路由与页面切换机制

**路由 key 对照表**（根 `app.js` → `pages` 对象）：

| key | 页面路径 | 显示名称 |
|---|---|---|
| `forecast` | `pages/demand-forecast/index.html` | 需求预测 |
| `stock` | `pages/stock-plan/index.html` | 备货计划 |
| `purchase` | `pages/purchase-plan/index.html` | 采购计划 |
| `shipment` | `pages/shipment-plan/index.html` | 发货计划 |
| `purchaseOrder` | `pages/purchase-orders/index.html` | 采购单 |
| `shipmentOrder` | `pages/shipment-orders/index.html` | 发货单 ✨ |

**切换方式两种**：
1. **根入口 hash 路由**（用户主要使用方式）：`index.html#shipmentOrder` → 读取 hash → 切换 iframe `src = pages[hash]`
2. **iframe 内部 postMessage**：iframe 内点击 `.nav-item[data-page-nav=X]` → `window.parent.postMessage({type:'prototype:navigate', page: X})` → 父窗口改 hash → 改 iframe src
3. **页面独立打开**（非 iframe）：`.nav-item[data-page-nav=X]` → `window.location.href = '../xxx-page/index.html'`

> 所有业务页面的侧边栏都使用同一套浅色导航结构，选中态样式一致（浅蓝背景 + 蓝色文字 + 右侧蓝边框）。
