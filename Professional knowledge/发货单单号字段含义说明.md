# 发货单单号字段含义说明

> 本文档说明发货单（易仓 ERP / 中台）上常见单号字段的含义与用途，便于产品、业务和研发统一口径。内容聚焦「跟踪号、参考号、服务商单号、总单号」四类容易混淆的单号。

## 一、跟踪号（Tracking Number）

- **作用**：查询物流轨迹。
- **谁给的**：物流公司 / 承运商。
- **用途**：货从仓库发出后，业务拿跟踪号到物流官网查询「是否开船、到港、清关、派送」等轨迹状态。
- **关联字段**：中台「物流单号」；采购单场景下的「采购跟踪号 TRK-xxx」也属同类作用。

## 二、参考号（Reference ID / Reference No）

- **作用**：自定义 / 系统生成的关联标识，用于「对号入座」。
- **谁给的**：自己或系统生成，非物流公司提供。
- **用途**：把发货单与其他单据或业务关联起来，便于追溯。
- **典型场景**：FBA 场景下亚马逊为货件提供 Reference ID，用于把中台发货单与亚马逊货件对应。
- **通俗理解**：像贴在外箱上的内部编号，方便自己认货，与物流单号是两回事。

## 三、服务商单号（承运商单号 / 物流服务商单号）

- **作用**：物流服务商（承运商）内部的单号。
- **谁给的**：物流公司 / 承运商。
- **用途**：在其系统内用于结算、对账、调度。
- **典型场景**：找头程物流商发货后，对方给出的系统单号，用于对费用、对账单。
- **关联字段**：中台「轨迹信息」中的「物流服务商单号」「承运商」。
- **与跟踪号的区别**：跟踪号偏「查询轨迹」，服务商单号偏「结算对账与内部调度」；二者可能是同一号，也可能不同。

## 四、总单号（合并总单号 / 主单号）

- **作用**：把多张小单合并成一张「大单」后的编号。
- **谁给的**：自己 / 系统合并生成。
- **用途**：解决「一票一件」单据过碎导致头程费用无法核算、无法对账的问题。
- **典型场景**：一个货件含多个 SKU，若每个 SKU 单独建单（一票一件），物流费与对账无法处理；将同批货的多张发货单合并成一张总单（一票多件），总单号即该大单的编号。
- **单号关系**：形成「父子单号」关系，总单为父，原小单为子，类似采购单的父级与子级。

## 五、速查表

| 单号 | 谁给的 | 用途 |
|---|---|---|
| 跟踪号 | 物流公司 | 查货到哪了 |
| 参考号 | 自己 / 系统 | 关联其他单据，方便对号 |
| 服务商单号 | 承运商 | 对费用、对账单 |
| 总单号 | 自己合并生成 | 多张小单合成大单，方便算费用 |
