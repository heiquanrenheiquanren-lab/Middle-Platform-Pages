# PRD 模板与写作规则

## PRD 定位

PRD 不是把前序材料重新抄一遍，而是把已经确认的业务目标、方案逻辑、页面交互、数据规则、异常规则、验收口径，整理成研发、测试、业务方都能对齐的交付文档。

PRD 不负责重新判断需求是否值得做，也不负责扩大范围。只写本次需求。

## 写作规则

1. 只写本次需求，不主动扩大范围。
2. 不做范围收缩，不主动规划一期、二期、三期。
3. 已确认内容和待确认问题必须分开。
4. AI 推测必须标注为"推测"或"待确认"。
5. 不要把待确认内容写成确定规则。
6. 如果资料不足，也可以生成 PRD 草稿，但必须列出待确认问题。
7. 涉及金额、税率、发票、结算、对账、付款、库存、财务确认、审计追踪时，必须补充合规、权限、数据口径和操作留痕内容。
8. PRD 要适合研发、测试、业务方评审使用。

## 轻量需求说明结构

轻量需求不一定需要完整 PRD，可使用以下结构：

1. 需求背景
2. 改动内容
3. 影响页面 / 字段 / 角色
4. 交互说明
5. 数据和权限影响
6. 验收标准
7. 风险提醒和待确认问题

## 标准 / 复杂 PRD 结构

### 一、文档信息

| 项目 | 内容 |
|---|---|
| 需求名称 |  |
| 需求模式 | 轻量 / 标准 / 复杂 |
| PRD 版本 | 草稿版 / 评审版 |
| 需求来源 |  |
| 适用系统 / 模块 |  |

### 二、需求概述

包括：
1. 背景说明
2. 目标摘要
3. 影响对象
4. 本次需求说明

### 三、业务价值

按实际情况输出：
- 供应链价值
- 业务部门价值
- 公司价值
- 员工价值
- 用户价值
- 风险控制价值

不要写空泛价值，要贴合当前需求。

### 四、业务流程

说明：
1. 当前流程
2. 目标流程
3. 关键业务节点
4. 用户操作节点
5. 系统处理节点

建议表格：

| 步骤 | 操作角色 | 操作 / 系统处理 | 输出结果 |
|---|---|---|---|

### 五、角色与权限

| 角色 | 查看权限 | 操作权限 | 数据范围 | 备注 |
|---|---|---|---|---|

重点写清谁能看、谁能操作、谁能审批/确认/退回、谁能导入导出，以及部门、供应商、仓库、区域、项目等数据范围。

### 六、功能需求

| 功能模块 | 功能说明 | 关键规则 | 备注 |
|---|---|---|---|

每个功能要说明页面入口、用户操作、系统响应，以及是否需要新增、编辑、查看、删除、导入、导出、筛选、分页、弹窗、抽屉等能力。

### 七、页面与交互说明

页面型需求应说明：
1. 页面结构
2. 筛选区
3. 列表区
4. 操作区
5. 详情页 / 弹窗 / 抽屉
6. 状态标签
7. 操作反馈
8. 空状态和异常提示

页面风格默认面向企业后台系统。后续 HTML 原型必须遵循 Element Plus + Vue 3 规范。

### 八、数据与字段规则

| 字段名称 | 所属对象 | 字段类型 | 是否必填 | 来源 | 规则说明 |
|---|---|---|---|---|---|

重点说明字段来源、字段口径、校验规则、枚举值、计算规则、空值处理、是否影响导入导出。

### 九、状态与业务规则

如果涉及状态：

| 状态 | 含义 | 可执行操作 | 状态变化规则 |
|---|---|---|---|

如果不涉及状态，说明"不涉及复杂状态流转"。

### 十、异常与边界场景

| 场景 | 触发条件 | 系统处理 | 用户提示 |
|---|---|---|---|

必须覆盖适用场景：必填缺失、权限不足、重复提交、数据不存在、状态不允许操作、导入/导出异常、接口失败、历史数据兼容。

### 十一、系统影响

| 系统 / 模块 | 影响内容 | 是否本次处理 | 备注 |
|---|---|---|---|

### 十二、合规与审计要求

如果需求涉及金额、税率、发票、结算、对账、付款、库存、财务确认、审计追踪，必须输出本章节。

包括：
1. 财务合规要求
2. 税务合规要求
3. 审计留痕要求
4. 操作日志要求
5. 数据权限要求
6. 敏感字段处理要求

如果不涉及，说明"不涉及明显财务、税务或审计要求"。

### 十三、验收标准摘要

先输出初版验收标准，不需要完整测试用例。完整测试用例在"验收前置"阶段生成。

验收标准必须可测试。

### 十四、待确认问题

| 问题 | 为什么重要 | 影响范围 | 建议确认对象 |
|---|---|---|---|

## PRD 草稿版与评审版

| 版本 | 用途 |
|---|---|
| PRD 草稿版 | 用于业务评审、内部讨论、快速对齐。允许有待确认问题。 |
| PRD 评审版 | 用于研发、测试、设计正式评审。待确认问题应尽量收敛。 |
